## 0. Headline findings

1. **Base input was written against a different text API from our core pin.** The workspace asks for `gpui-ce = "0.2.2"` from crates.io. Base's Cargo.lock resolves that to the registry artifact (checksum b0af79c6…, lock line 3057). That artifact depends on `core-text`, `lyon`, … and **has no parley anywhere**: `grep parley Cargo.lock` returns nothing, and `gpui_ce_windows` 0.1.0 has no parley dependency either. The core pin also says `version = "0.2.2"` (P:../Cargo.toml:3), but it is the later **Parley** text system (`gpui_windows` → `gpui_parley`, P:../../gpui_windows/Cargo.toml:34). Base calls these APIs, none of which exist in the pin:
   - the 4-argument `shape_line(text, size, runs, force_width)` (U:base/element.rs:1049-1062). The pin has 3 arguments (P:text_system.rs:325).
   - `ShapedLine::x_for_index` / `index_for_x` / `closest_index_for_x` (U:editor/display_map/inline_line.rs:47-86, text_wrapper.rs:728-904, element.rs:724,1797,1970). The pin has **no** `fn x_for_index`; grep of P: finds nothing.
   - `TextSystem::line_wrapper` + `gpui::LineFragment::{text,element}` + `wrap_line` (U:editor/display_map/text_wrapper.rs:296-335). These are absent from P:.
   - `TextSystem::layout_width(font_id, size, ch)` (U:base/element.rs:2397). Absent from P:; the pin has `advance` (P:text_system.rs:177).

   So this is a **re-targeting port, not a transliteration**: every geometry call must be re-expressed over the pin/Go `WrappedLine` model (Caret / HitTest / SelectionRects / Line ranges). This contradicts research/00-baseline.md §"Why CE" point 1 ("written against the same core API line"). That is true for the version string, but false for the text system. **Flag for the baseline owner.**
2. **IME/input handler: PRESENT and usable from an external package.** `(*Window).HandleInput(FocusHandle, InputHandler)` (G:input.go:60) works with any type that also implements `gpui.IMEInputHandler` (G:ime.go:135-170). The WM_IME_COMPOSITION driver (G:ime.go:382) and the candidate-window push (G:ime.go:240) use only these exported members. Gaps (MISSING-GO, small):
   - no `ElementInputHandler`/`EntityInputHandler` adapter: each Go handler carries its own element bounds; see G:editor.go:183, ElementBounds.
   - no `Paste` hook, `PrefersIMEForPrintableKeys`, `TextInputConfiguration` or `TextInputEditableRange` (P:input.rs:68,134,143,288). The configuration/editable-range members only matter on mobile/macOS.
3. **Shaping and geometry are PRESENT, via `DefaultTextSystem().ShapeText` → `*WrappedLine`** (G:text.go:483). It has multi-run fonts, fallbacks, wrap, carets, hit tests, selection rects and clusters. **Painting is not reachable from an external element:** `frame.scene` and `frame.paint` are unexported (G:div.go:363, inline_real.go:89). There is no exported `PaintQuad`/`PaintPath`/`PaintUnderline`/`PaintText` keyed on `*Window`; only `PaintSvg` is exported (G:svgelement.go:383). → MISSING-GO, and a hard prerequisite.
4. **Per-run color, underline, strikethrough and background: native lacks the run→glyph mapping, but there is a Go workaround.** The pin's `PaintFragment` carries a `PaintStyle` per fragment (P:text_system/line_layout.rs:405-435). The native ABI's run record has no paint fields (N:text.rs:327, NG:text.go:242-255). Its fragment record (N:text.rs:518-533) and glyph record (N:text.rs:543-553) carry **no byte range or run index**, and every native run is built with `..TextRun::default()` paint (N:text.rs:1099-1109). The core port already documents the result: "per-run paint styles are outside the port's run surface" (G:inline_real.go:42-45). Workaround without native changes: for each style run, take `SelectionRects(run.start, run.end)` (bidi-correct x-intervals) and color each glyph whose `X` falls inside. Decorations and backgrounds come from the same rects plus `FontMetrics.UnderlinePosition`/`UnderlineThickness` (G:text.go:244). Residual fidelity loss: a ligature that straddles a color boundary takes one color. **Not a blocker.**
5. **syntect is not used by Base src at all.** It is only used in examples/showcase/syntect_highlighter.rs. Highlighting is a parser-agnostic seam (`InputHighlighter` trait, U:editor/highlighting.rs:22-63), so no syntect port is needed.
