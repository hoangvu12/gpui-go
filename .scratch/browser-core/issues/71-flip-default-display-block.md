## Answer

- **Where the default lives now**: `gpui/style.go` `DefaultStyle()` carries `Display: DisplayBlock` (the `Display` const docs and the `DefaultStyle` doc note the D6 divergence from the pin's Flex). The ABI-level `internal/native/layout.go` `NewLayoutStyleRecord` KEEPS `DisplayFlex` — it is the Taffy default style the pin forwards, and `styleToRecord` always writes the style's own Display, so the record's default only serves direct ABI consumers; `gpui` `TestStyleToRecordDefaults` now pins exactly that divergence (every field equal except Display: Block tag vs the record's Flex).
- **Constructors pinned** (69's non-Styled list — all childless/measured leaves whose display cannot change their own layout, since Taffy only uses a node's display for its own children and the inline collector classifies Flex and Block identically; the pins keep the nodes exactly at the pin's value): `Svg()` (svgelement.go), `Text` (textNodeStyle, style.go, used by div.go's textElement request/layout-node style), `NewStyledText` (styled_text.go ×2 via the same helper), `List` (listelement.go), `UniformList` (list.go); plus the same pin-fidelity pins for `TextSelectionLayer` (text_selection.go) and `NewSurfaceElement` (capture.go). Verified as already pinning internally: `Anchored` (anchored.go:470), `TopLayer` (toplayer.go:1048), `Empty` (DisplayNone, element.go).
- **TSX**: 69's pin removed from `Host.lower` (gpui/script/lower.go) — a TSX `<div>` follows the block default like HTML. The `<text>` tag is the host's text-run sugar, NOT a div, and keeps the pin's flex shape (`Node.isTextElement`): with the block default every styled run became a per-frame inline paragraph and the sidebar-shaped trees (200+ runs) measured ~100 ms/frame of repeated line queries; with the sugar pin the timing test is back at the base numbers (paired overhead 0.486 ms). `.tsx` files touched: `gpui/script/testdata/sidebar.tsx` only (its counter div gains `flex` in the className — the one div there that relied on the old default). app.tsx/surface.tsx/errors.tsx/tsxslots/*.tsx/tsxtracer/view.tsx needed no additions: their divs already state flex or their Chrome page twins are plain block divs — the tsxtracer box and the tsxslots greeting now match their pages MORE closely under the block default (both fixtures still pass all three tiers). `go generate ./examples/tsx-hello` and `go generate ./gpui/script/types` are no-ops (no class/style-key changes; bundles unchanged).
- **Fixture views unpinned**: 138 `.Flex()` pins removed across 32 fixture view files — every view div whose Chrome page twin is a plain (block) div. Pins stay where the page itself says `display: flex` (roots/bodies, scrollers, flex rows/columns, the `.row`/`.swatch`/`.box` families) and where the fixture's machinery was built against the flex text path (userselect/selection's text divs: the selection gesture's measured-leaf text child — unpinning failed their selection tests, so the pin is restored with a comment; a follow-up can move selection onto paragraph fragments). Also removed the now-inert `FlexCol()` from fixed.go's scroller (its page twin is a plain block scroller).
- **New fixture**: `internal/parity/fixtures/displayblock` (display-block): plain divs with no display set anywhere but the contrast sibling — stacked children, auto widths filling the containing block (b2 400, inner 372, para 600), an explicit-width child with an inline margin (b1), a nested block, a text child (the paragraph), an explicit `display: flex` sibling with a row of two children. Registered in replay_test.go and cmd/parityrecord/main.go, recorded with `GOFLAGS=-p=4 go run ./cmd/parityrecord -fixture display-block` (Chrome/155.0.8059.85, 10 boxes, 0 events). All three tiers pass, the headroom test passes, and the deliberately-wrong view (the pre-71 flex default, at most one) fails Tier A on the unstacked/unstretched boxes (displayblock_test.go).
- **Chromium citation**: in-flow block children stack at the running block offset (`BlockLayoutAlgorithm::Layout`'s `BlockChildIterator` loop, third_party/blink/renderer/core/layout/block_layout_algorithm.cc:974-1075) and a parallel-flow, non-replaced block child with `justify-self: normal` gets `SetInlineAutoBehavior(AutoSizeBehavior::kStretchImplicit)` — the auto inline size fills the available inline size minus inline margins (block_layout_algorithm.cc:3490-3500, gated by `ShouldBlockContainerChildStretchAutoInlineSize`, core/layout/space_utils.cc:82-102; CSS2.1 §10.3.3 rule 3).

- **Divergence note**: the pin's `Style::default()` display is Flex; gpui-go's `DefaultStyle` is Block (D6, browser wins). Fixed en route: the inline paragraph's measure cache (gpui/inline.go) — the D2 note describes nil/zero/definite wrap widths as "distinct entries" but the code kept one slot, recomputing the native shaping on every interleaved query; it is now three slots keyed by sizing mode.
- **Gaps** (noted, not implemented): margin collapsing is unverified against Chrome at the gpui level (Taffy 0.13's block algorithm carries it; the fixture avoids vertical margins); floats are structurally absent (no float property, the native build enables no float_layout feature); the full CSS anonymous-box model is not implemented (the inline collector's paragraphs cover the tested shape — one run of inline content between block children; mixed inline/block children in one box are exercised only through that path).
