## Answer

- **The surface is generated, never hand-written** — `internal/tsxgen` (package `tsxgen`) extracts it from the code that accepts it: `Extract` (internal/tsxgen/tsxgen.go:104) parses `jsxElement`'s element/prop switches, `eventObject`'s fields and `hostGlobalNames` (gpui/script/host.go), `parseStyle`'s keys with each case's value shape read from the code (gpui/script/node.go), the method-class switch of gpui/class_generated.go (cross-checked against its `methodClassCount`), specialClass/scrollClass/parseVariant and the length/color/grid/scale tables of gpui/class.go, and the palette of gpui/tailwind_palette_generated.go. An unrecognized shape is an error, so a new style key/element/prop/global fails generation loudly. `cmd/tsxdtsgen` writes `gpui/script/types/gpui-script.d.ts` (1851 lines, committed, byte-idempotent, `go generate ./gpui/script/types`); the class families' value shapes (spacing, brackets, opacity, typography, borders, gradients, filters) are declared in tsxgen and verified against the engine's behavior (below).
- **The .d.ts** — `gpui/script/types/gpui-script.d.ts`: `Class` (every method class, palette color × 5 prefixes, length family × the value grammar, opacity/grid/aspect/typography/border/ring/filter/blur/gradient arms, `group`/`group/name`), `HostProps` (key, id, className, style, onClick, onMouseDown, children), `CSSProperties` (all 19 keys with their exact value shapes: enums, `number | \`${number}px\``, `\`#${string}\``, flex `1`, padding 1/2/4-length forms), `MouseEvent` (button, x, y, the four modifier keys), the JSX namespace (div, text, Fragment) and all 25 host globals with signatures. `gpui/script/types` (types.go) embeds it; `types.DTS()` serves it; `go list -deps ./examples/tsx-hello` contains no `gpui/script/types` — release apps link none of this.
- **The drift tests (no tsc needed)** — `internal/tsxgen/tsxgen_test.go`: `TestDTSIsCurrent` (regeneration is byte-identical — any engine change without regenerating fails), `TestDTSDeclaresTheEngineSurface` (`ParseDTS` reads the committed file back and `Compare` checks both directions: elements, props, events, event fields, style keys with types, globals with signatures, class aliases + the Class type), `TestPlantedGapsFailTheParityCheck` (eight planted gaps — a removed class, style key, element, prop, event field, global, alias arm, and a changed style type — each must fail the parity check), `TestClassTypesMatchTheEngine` (everything the types accept, `gpui.CheckClasses` accepts — 507 literal arms + every template arm sampled with variant/important compositions; everything the engine accepts from its tables and from a 16k-candidate probe over the Tailwind utility namespace is matched by the Class type), `TestParseRoundTrip`.
- **The engine side** — `gpui/script/dtsurface_test.go` (internal): every declared style key/value runs through `parseStyle`, every element × prop through `jsxElement`, `eventObject` has exactly the declared fields, and the fixture covers every style key/element/event. `gpui/script/surface_test.go`: `testdata/surface.tsx` (the whole surface in one view — all 19 style keys, both events, div/text/Fragment, a function component, state/bind/useState, classes) compiles through esbuild, runs through goja, updates bound values without re-describing and fires both handlers (`Host.MouseDown` added as Click's twin, gpui/script/host.go:365).
- **The check command** — `cmd/tsxcheck [-typescript path] [-strict] [-init] <dir-or-view.tsx>`: runs tsc (`--noEmit --jsx react --jsxFactory h --jsxFragmentFactory Fragment --target es2017 --lib es2017 --pretty false`, tsc's classic-JSX flags matching esbuild's factory) over the sources with the module's current .d.ts; exit 0 clean / 1 diagnostics / 2 usage / 3 no tsc. tsc discovery (gpui/script/types/check.go:184): the `-typescript` flag or `GPUI_TYPESCRIPT` env, then a typescript package in node_modules above the sources, the npm global install, then tsc on PATH; nothing is installed and the no-tsc error names every location and the fix. **tsc is not installed on this PC** (node v24.18.0 is present, no tsc anywhere the discovery looks — verified with `where tsc`); the tsc-dependent tests skip with that message, and the drift tests (Go, no tsc) carry the parity requirement. For verification I ran them against a typescript 5.9.3 that already exists in another project on this PC via `GPUI_TYPESCRIPT` (no install, no global change): the clean fixture passes, and the error sample is caught — misspelled style key (TS2561 with a "did you mean" hint), bad value (TS2322), unknown prop (TS2322), bad Class (TS2820). Measured: a full check of the 39-key fixture is ~0.7 s.
- **Debug builds check after each reload** — `script.WithTypeCheck(types.NewChecker(dir))` + `WithTypeDiagnostics` (gpui/script/typecheck.go): after every successful reload the host runs the checker off the host thread (scheduler `Run`/`Post`, the fetch model; synchronously without a scheduler), reports diagnostics through the hook (stderr default), never gates the running UI, skips after failed reloads, and drops the result of a check a newer reload replaced. The host imports no type-checking package — `TypeChecker` is an interface, so an app opts in and a release build links none of it.
- **Tests/commands** (all headless, no windows, no real input): `go test ./internal/tsxgen ./gpui/script/types ./cmd/tsxcheck ./gpui/script` and `./internal/parity/...` all ok (`-p 1 -count=1`), including ticket 62's timing thresholds and the tsxtracer fixture. `go vet`, `gofmt -l` and `go build ./...` clean.
- **Limitations** (documented in the .d.ts and doc.go): className stays `string` — a class list is space-separated and unbounded, and TS unions over lists explode (measured: minutes); the engine validates every class at load with file:line, and the generated `Class` type covers single classes (every palette color, scale value, bracketed length and modifier — ~507 literals + 98 template arms, checked in 0.7 s). Variant/`!`-prefixed forms compose over `${string}` tails for the same reason (the engine strips and validates the class left, exactly as it validates a list). `${number}` accepts exponent/non-0.25 forms the engine rejects at load. A brand-new class family whose prefix is outside the Tailwind utility namespace (the candidate probe's coverage) would not be caught by the forward direction; the parsed tables (method classes, palette, scales, prefixes) cannot drift silently. No `tsc` on this machine: the tsc-catching acceptance was verified through `GPUI_TYPESCRIPT` pointing at an existing local typescript 5.9.3; the committed tests skip without it.
