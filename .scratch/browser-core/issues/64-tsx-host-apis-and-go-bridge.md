## Answer

All in **`gpui/script`** (three new files, `scheduler.go` / `globals.go` / `bridge.go`, plus the host/view/doc changes; nothing outside `gpui/script`, so the import graph and the no-goja-in-`gpui` guarantee are unchanged).

**Globals provided, and why.** `setTimeout`/`clearTimeout`, `setInterval`/`clearInterval` (shared id pool, either clears either, arguments passed through, negative/NaN delays clamped to 0), `queueMicrotask` (built on `Promise.resolve().then`: goja drains microtasks when the current Go→JS call returns — exactly the browser's "after the current task"), `requestAnimationFrame`/`cancelAnimationFrame`, `fetch`, `console` (log/info/debug/warn/error/trace/assert, devtools-shaped formatting with depth-2 truncation and %s/%d/%f/%j/%o; stderr by default, `WithConsoleSink` for the app), `performance.now()` (the scheduler's clock), `atob`/`btoa` (browser leniencies: whitespace ignored, missing padding tolerated), `TextEncoder`/`TextDecoder` (UTF-8; invalid bytes → U+FFFD, or an error with `{fatal: true}`), and `URL`/`URLSearchParams` (parsed by net/url; URLSearchParams is the prelude's, so WHATWG behaviour holds where net/url differs: '+' is a space, insertion order in `toString`, init from string/pairs/object, entries/keys/values/forEach). Priority reasoning: timers/fetch/console are what browser-trained (and LLM) code reaches for first; TextEncoder/URL are cheap and stdlib-backed; **not** provided, deliberately: `Intl` (needs CLDR/ICU-scale data; nothing in the surface needs it — a ticket can add the pieces that matter), `crypto`/`location`/`navigator`/`document`/`window` (the host is not a page; 67 adds capability-scoped ones). fetch's Response is browser-shaped: `status`, `ok`, `statusText`, `headers` (lower-cased, duplicates joined), `url`, `text()`, `json()` (rejects a non-JSON body with a SyntaxError); a network failure rejects with a TypeError naming the URL and reason; non-2xx resolves; relative and non-http(s) URLs are named errors (there is no base URL). The transport is the host's (zgui's `ScriptHost::fetcher`): the default is a plain `net/http` client, `WithFetcher` installs the app's — which is also 67's gate point for a plugin's network grant.

**The Go bridge.** Actions: `host.Action(name, func(args []any) (any, error))` (quick — runs inline on the host thread) and `host.AsyncAction(name, func(ctx, args) (any, error))` (off-thread; ctx is cancelled by a reload). Script side: `invoke("name", ...args)` returns the value (an error surfaces as an exception naming the action; an async action tells the script to use `call`) and `call("name", ...args)` returns a Promise — sync settles immediately, async settles from the host thread; goja runs async/await natively, so `await call(...)` works. Arguments and return values are goja-exported Go values (JSON-shaped: nil, bool, string, numbers, []any, map[string]any). Shared state: `script.NewShared()` + `WithShared(store)`; the script uses `shared(key, init)` — the same `{key, get, set}` handle shape as `state`, so `bind` works over it — and Go reads/writes `store.Read/Write`. A write from either side recomputes only the bindings on that key (no re-describe, `DescribeCount` guard in tests) and redraws; values live in the store so they survive reloads and outlive the host; `state:` and `shared:` keys are distinct namespaces. **The 67 seams:** `WithActionResolver(ActionResolver)` replaces the name→action lookup, and `SharedStore` is the store interface — a plugin host installs a gated view of the app's store and a grant-checking resolver, and a script reaching past them gets a named missing-grant error (the resolver test shows the exact shape: `action "secret": the script was not granted it`).

**Threading model.** goja is single-threaded; all JS runs on the thread that renders. The seam is `script.Scheduler` (Post / After / Run / Now), adapted by `AppScheduler(app)`: timers ride `SpawnDelivering` + `TaskRun.Sleep` (the worker parks on its first request, so driving it never blocks the dispatcher; equal deadlines fire in registration order through the scheduler's FIFO; `Task.Cancel` is clearTimeout); fetch and async actions run their blocking work on goroutines the scheduler owns — never a scheduler task, whose body the dispatcher drives inline to its first park point, which would park the whole UI on a slow HTTP round trip — and settle their promise by marshalling back through Post (a spawn arriving after shutdown is dropped, not fatal). Microtasks drain inside the Go→JS call. Under `TestApp` the clock is virtual: `AdvanceClock` fires timers and their foreground continuations synchronously — the timer tests are fully deterministic; the real-server fetch tests poll `RunUntilParked` to a deadline (localhost settles in the first iterations; the injected-fetcher and abort tests stay deterministic). `requestAnimationFrame` callbacks run at the window's next frame request (`View.Render` schedules `Window.OnNextFrame`), before that frame paints — what they change shows in the frame they were drawn for; the timestamp is the scheduler clock. `View` also auto-wires the scheduler from the window's app on first render, so a mounted host needs no explicit setup; without a scheduler the host still loads and runs handlers, and the globals that need one raise a named error that says the fix.

**Reload behaviour.** Each `Load` builds a VM generation. A successful reload drops everything the replaced VM had pending — timers and intervals cancelled, in-flight fetches and async actions aborted (context cancelled, promises never settle — the browser aborts in-flight fetches on navigation; a completion that still lands is dropped by generation check), pending rAF callbacks and unhandled rejections dropped — while keyed state and the shared store keep their values. A **failed** load keeps the old VM with its tree, timers and completions running (the last good UI still works, timers still fire). Tested both ways, including an interval surviving a failed reload and dying on a good one.

**Tests** (all through the public API, headless, no visible windows, no `GPUI_REAL_INPUT_TESTS`): `timers_test.go` — deadline firing on the virtual clock, clearTimeout, FIFO order for equal deadlines, deadline order, callback arguments, interval repeat + clearInterval + the 35 ms clear case, a throwing timer reported but the host stays alive, timer-driven bound updates without re-describe, cancellation across a good and a failed reload, the no-scheduler named error, queueMicrotask ordering (before timers, after the synchronous part) and error reporting, performance.now on the virtual clock, rAF drives the next frame with the frame timestamp, cancelAnimationFrame, rAF callbacks dying with the reload, a timer update redrawing the window, and a Go shared write redrawing the bound UI in a window. `fetch_test.go` — local httptest server: success (status, ok, headers, body via text()), 404 resolves with ok=false, a closed server rejects with the URL, json() parse + SyntaxError on a bad body, method/headers/JSON body round trip, relative URL named error; the injected fetcher; a fetch in flight across a reload never settles (ctx cancelled, nothing surfaces, the new VM runs); the no-scheduler error. `bridge_test.go` — invoke arguments (all JSON shapes), return values, action errors as exceptions naming the action, unknown action, invoke-on-async guidance, call settling sync and async, call rejection, an async action in flight across a reload never settling, `await` inside handlers, the resolver seam answering a named grant error, shared round trips (script→Go, Go→bound UI, windowed too), survival across reloads and hosts, state/shared namespace separation, the missing-store named error, SetGlobal collisions on all the new names. `globals_test.go` — console formatting (each shape), the sink, atob/btoa round trip + invalid input, TextEncoder/Decoder round trip, U+FFFD replacement, fatal, unsupported labels, URL parsing/resolution/fields, URLSearchParams browser semantics + insertion order, unhandled rejection reported, handled rejection not.
