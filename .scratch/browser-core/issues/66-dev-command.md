## Answer

- **The command: `cmd/tsxdev`** — `go run github.com/hoangvu12/gpui-go/cmd/tsxdev .` from the app's package directory (flags: `-state`, `-tags dev`, `-poll 200ms`, `-debounce 250ms`, `-grace 5s`). It builds the app, runs it as its one child, and watches the package tree: a `.tsx/.ts/.js/.json` change sends `reload` (an in-place `Host.Reload`, keyed state kept); a `.go/go.mod/go.sum` change **builds first** (a failed build keeps the running app up, the mirror of a failed reload keeping the last good tree), then asks the app to save and exit, waits (`-grace`), kills only that process if it lingered, and starts the rebuilt binary — which restores. The app opts in with a dev-mode file behind the `dev` build tag; the supervisor builds with `-tags dev` (a release build of the same app embeds the bundle and links no esbuild — `go list -deps` proves both, as in ticket 65).
- **The restart handoff** (one implementation per half, so they cannot drift): the `GPUI_DEV_STATE` env var names a JSON state file, and the child's stdin carries newline commands `reload`/`save` (unknown lines logged, ignored). On `save` the app writes `{state, shared, window}` atomically (temp+rename) and exits 0; on startup it seeds from the file. The supervisor never interprets the file — it is a handoff between two runs of the app. The protocol is documented in full at gpui/script/dev.go.
- **What survives a restart:** the host's keyed state (`Host.StateSnapshot` → `WithStateSnapshot`), the shared store's values (`Shared.Snapshot`/`Restore`), and the window's logical bounds — saved from `Window.Bounds()`, restored with `Window.SetBounds()` (the public window API; nothing private). The two round-trip exactly: the Win32 host's placement math once split the frame extent symmetrically (the reference's `calculate_window_rect`) while a caption window's client area sits one caption below that split, so every save→restore moved the window by ~12 logical px; `windowRectFromClient` now places the client origin from the measured offsets (`ClientToScreen` minus `GetWindowRect`, gpui/win32host_windows.go updateBorderOffset/windowRectFromClient), making `SetBounds(Bounds())` a no-op up to device rounding — pinned by `internal/winhostspec/bounds_test.go` (creation lands on the requested origin as the OS itself reports it; three consecutive round trips do not move the window) and by the e2e below. Timer/fetch/async-action state does not survive a restart (new process), only a reload.
- **The gpui/script hooks** (gpui/script/dev.go): `DevEnv`/`DevHeadlessEnv` consts, `DevState`/`DevBounds` + `ReadDevState`/`Save`/`WindowBounds` (gpui/script/dev.go:108-196), `Host.StateSnapshot` (:203) and `WithStateSnapshot` (:216), `Shared.Snapshot` (:226)/`Restore` (:240), and `RunDev(DevConfig)` (:317) — the command-stream half that marshals `reload`/`save` onto the thread that renders (the doc.go threading model), keeps the last good tree on a failed reload, and exits through `Window.Close` after a save. The supervisor: `Supervisor.Run` (cmd/tsxdev/supervisor.go:81), `restart` (:141), `swapOut` (:175), the `goBuilder` (:278) and `execSpawner` (:316, child in a new process group so Ctrl+C reaches the supervisor alone; kill = `cmd.Process.Kill` of the exact child, never another process). The watcher (cmd/tsxdev/watcher.go:57) is a poll (default 200ms) with content hashes (Windows updates a same-size rewrite's mtime lazily) plus a debounce (:168) that collapses a burst into one action — no busy loop. Signals, a `quit` stdin line or a closed stdin pipe stop the session the graceful way (cmd/tsxdev/main.go:175-216). doc.go's "The dev command" section is the usage guide.
- **The sample app, both shapes:** examples/tsx-hello's `main()` dispatches on `GPUI_DEV_STATE` to `runDev` — `dev.go` (dev-tagged): `compile.Open` + `WithStateSnapshot` + `Shared.Restore` + the reload-time type check (ticket 63) + `SetBounds` restore + `RunDev`; `dev_stub.go` (!dev) refuses the env with the fix named. The shared window/app boilerplate is `runApp` (examples/tsx-hello/main.go:139), used by both `run()` and `runDev()`. The headless env (`GPUI_DEV_HEADLESS=1`, passed through by whoever runs the supervisor) opens the window far off the desktop, never activates, and moves it once — a simulated user drag — so a restart's position restore is observable without a screen.
- **Tests** (headless, no visible windows, no real input): `gpui/script/dev_test.go` — the state file round trip (bounds/shared/keyed, corrupt → fresh), keyed state + shared surviving a **simulated restart** through the real file, and the command stream (an injected pipe: unknown line ignored, reload picks up new sources in place with state kept, a failed reload keeps the last good tree, `save` writes state/shared and exits, EOF ends the session). `cmd/tsxdev/supervisor_test.go` — the supervisor's decisions against a **fake builder/child** (no real rebuilds): reload on .tsx, restart on .go (save → exit → rebuild → replacement), kill after grace when it lingers, a failed rebuild keeps the app, retry of a failed first build, session ends with the app's exit code, graceful stop. `watcher_test.go` — classification and the same-size-rewrite detection, the debounce collapse. `internal/winhostspec/bounds_test.go` — the bounds round trip is exact (the drift fix). `cmd/tsxdev/e2e_test.go` — **one end-to-end test**: builds the real supervisor, copies examples/tsx-hello to a temp module, seeds state, runs the app off-screen under the supervisor, edits the .tsx (in-place reload, same pid, label changed, clicks kept), then edits main.go **twice** (two rebuilds, two graceful restarts: each new pid, keyed clicks + the key the reloaded .tsx added + the moved window position restored **exactly** — the third app's position equals the seed plus the three explicit drags, nothing else; a per-restart offset would show up doubled), then stops gracefully; it **skips with a measured reason when the machine is too loaded to stay under ~60s**. `gpui/script/typecheck_internal_test.go` — the same checker error (the no-tsc discovery) is reported once per session and a different one is news.
- **Measured edit-to-screen** (e2e run, test flags poll=100ms debounce=250ms; defaults add ~100ms): .tsx edit → reload command sent **251-252 ms** after the change (the debounce dominates; the reload itself is ticket 62's ~4 ms); .go edit → app restarted **4.3-5.6 s** after the change (2.8-2.9 s build warm; 25.8 s on this loaded machine); a whole session including both edits, two restarts and the graceful stop ran in 21 s (47 s under load). Both paths' lines are printed by the supervisor (`reload sent, 251ms after the change`).
- **Limitations:** the watch covers the app's package directory (an app whose .tsx live elsewhere gets no reload — the sample's `ui/` beside `main.go` is the shape); a mixed .tsx+.go save restarts without a separate reload (the fresh app loads current sources); the child must not spawn its own processes (a kill ends only the child, leaving its orphans — none exist today); no cross-session persistence by default (the state file lives in the supervisor's temp workdir — `-state` overrides); tsc is not installed on this machine, so the dev type check reports the no-tsc error once per session and then stays quiet (ticket 63's discovery contract; a restart says it again, once).
