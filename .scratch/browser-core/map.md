# Browser core: implementing the browser-parity spec

Labels: wayfinder:map

## Destination

Implement [the spec](../browser-parity/spec.md):
- a browser-like gpui-go core (the browser wins over the GPUI-CE pin, D0)
- TSX UI scripting ([ADR 0003](../../docs/adr/0003-tsx-ui-scripting.md))
- the R15 and R16 native rebuilds
- the performance track
- Base moved to a local `gpui-go-base` repository

The user approved the 76-ticket breakdown on 2026-10-23 ("looks good").

## Notes

- Tickets are in `issues/`, numbered in dependency order. Each lists `Blocked by`.
- The frontier is every open, unassigned ticket whose blockers are all resolved. At the start these have no blockers: 01 (the harness), 02, 03, 30, 31, 39 (R15, approved), 47, 49 (the R16 design, for human review) and 68 (the display codemod). Most tickets wait on 01.
- The main test seam is the browser-parity harness (01): HTML fixtures recorded once in headless Chrome, replayed against the gpui-go view in a headless window. The native spec packages, the TSX host through the same harness, and Base against the public API are the other seams.
- R16 (50-53) works on one integration branch. Green is promised only at 54, which needs the user's approval for the rebuild.
- Rules:
  - At most 6 workers (raised from 3 by the user on 2026-10-24), each in its own worktree.
  - Verify worker claims.
  - No push, tag or GitHub repo creation without the user.
  - Headless and offscreen by default.
  - Never set `GPUI_REAL_INPUT_TESTS=1` for a full run while the user is on the PC.
  - zterm and the gallery are never pushed.

## Decisions so far

- [01 - Browser-parity harness](issues/01-browser-parity-harness.md): `internal/parity` + `cmd/parityrecord` + guide `docs/browser-parity-harness.md`. Fixtures run at device pixel ratio 2, mapped by `data-id` and `.ID().DebugSelector()`. Records come from headless Chrome over a raw DevTools websocket. Replay uses the hostless test window and real text system, with pixels rendered through a hidden off-screen window. Tier C tolerances are provisional (at least 2x the measured correct values). The pin's click-before-mouseup gap was closed by 12. Fixture size is limited to the screen height (~1060 device px).

- [49 - R16 compositor design](issues/49-r16-design.md): approved 2026-10-24 ([docs/design/r16-compositor.md](../../docs/design/r16-compositor.md)). One effect-group mechanism and a target pool where overflow warns. Property-only frames are automatic, damage is capped at 16 regions, gradients take up to 64 stops, and DComp partial present happens only after a readback test. 50-53 now also wait on 39. Rev 16 (54) still needs approval.
- [39 - R15 native rebuild](issues/39-r15-native-rebuild.md): native rev 15, DLL `8b944eae…` (static CRT).
  - Working: Chrome's Windows bold rule (≥600 over a face <600); gradient backgrounds with CSS line length and premultiplied sRGB; colour-matrix filters; pixelated sprites with a point sampler; drop shadows clipped out of the border box; backdrop crop with mirrored margins; flow-root; grid track lists; justify-items/self.
  - Patched shaders are compiled from a vendored copy (`native/shaders/` + `native/build.rs`); ce-source is untouched. R16 should build on this.
  - GAP: the text-run fields and the measure baseline only pass through the ABI, so 42 and 43 need a follow-up native change.
- [64 - TSX host APIs and Go bridge](issues/64-tsx-host-apis-and-go-bridge.md):
  - Globals: timers, requestAnimationFrame, queueMicrotask, fetch (injectable `Fetcher`), console, performance, atob/btoa, TextEncoder/TextDecoder and URL/URLSearchParams. There is no Intl, crypto, window or document.
  - Go bridge: `invoke`/`call` run Go actions, and `shared(key)` / `NewShared` hold shared state that survives reloads and works with `bind`. `WithActionResolver` is the hook ticket 67 uses for plugin grants.
  - Threading and reload: goja is only ever touched on the host thread. A good reload cancels the old VM's timers and in-flight fetches.
- [09 - Default actions after listeners](issues/09-default-actions-after-listeners.md): Tab navigation, keyboard scrolling (40 px per arrow, Chrome's page step, Home/End) and Space/Enter activation now run after key listeners, and `PreventDefault` skips them. Bindings still win by default; `WindowOptions.KeyDispatchOrder` / `SetKeyDispatchOrder` gives the full browser order (D5). It also fixed a doubled keystroke-observer call. The harness gained keydown/keyup with key and focus fields, `data-events`, and `--disable-smooth-scrolling`. Escape has no default yet (16, 22).
- [10 - Hover enter/leave](issues/10-hover-enter-leave.md): `OnPointerEnter`/`OnPointerLeave` in Chrome's order (leave child-to-parent, then enter parent-to-child, before the move). WM_MOUSELEAVE now dispatches `MouseExitEvent` and clears hover. Typing no longer clears hover (D12). The harness gained `pointerenter`/`pointerleave`; there's no `mouseover`/`mouseout` yet.
- [40 - Gradient backgrounds](issues/40-gradient-backgrounds.md): `LinearGradientBackground` / `LinearGradientToBackground`, including CSS's corner angles, plus the Tailwind classes `bg-linear-to-*`, `bg-linear-<deg>`, `from-*` and `to-*`. Two stops only, drawn in sRGB. `via-*` and oklab (Tailwind v4's default) are rejected with named errors until R16 (52). This is a recorded divergence from Tailwind's oklab midtones.
- [08 - Rasterization and italic probes](issues/08-rasterization-and-italic-probes.md) (report: `research/browser-parity/08-raster-probes/`): **R17 text gamma/contrast: NO.** Mean ink is within 0.95-1.005 of Chrome across colours and sizes. **Italic slant: YES, needs a native fix.** Chrome shears synthetic italic by -0.25 (-14°); gpui-go's DirectWrite oblique shears -0.34 (-18.8°). The gap the probe did find is AA-mode selection: Chrome drops LCD above 48 device px and on non-opaque layers. The harness gained `Fixture.ChromeFlags` and `parity.MeasureInk`.
- **Native follow-up, rev 15.1: approved by the user on 2026-10-24, DONE as [77](issues/77-r15-1-native-follow-up.md) (see its gist below; the text fields are still blocked):**
  - Wire the rev-15 text-run fields and the measure baseline into shaping and layout (42, 43).
  - Fix the italic shear (08).
  - Fix the extension-uniform upload: draw.rs:2327/2330 `update_buffer(..., &[*uniforms])` copies an 8-byte reference instead of the struct. This makes every colour filter a no-op (41), and most likely zooms the backdrop crop (04). Acceptance: unskip the three filters fixtures and re-register shadow-backdrop.
- [62 - TSX host tracer](issues/62-tsx-host-tracer.md): `gpui/script` (goja host: keyed state, bind, useState as the slow path, reload with an error banner showing file:line) and `gpui/script/compile` (esbuild, dev only; release builds embed a prebuilt `script.Bundle`, kept out by the import graph rather than a build tag). The host adds 11.5 MB to a release binary, or 15.3 MB with the dev compiler. The element/style surface is small for now (div, text, Fragment, the probe's CSS subset). The TSX twin of the tracer passes the harness.
- [27 - System preferences](issues/27-system-preferences.md): `App.SystemPreferences()` and `App.SystemColors()` (19 CSS system colours), plus `OnSystemPreferencesChanged`. It covers colour scheme, reduced motion, forced colours, contrast (Chromium's 7:1 / 2.5:1 rule), reduced transparency, accent colour, caret blink and text scale. It refreshes on WM_SETTINGCHANGE, WM_SYSCOLORCHANGE, WM_THEMECHANGED and DWM colourization changes. Registry-only changes aren't watched, and a host with no window gets no broadcasts.
- [05 - Box painting fixes](issues/05-box-painting-fixes.md): the overflow clip always insets by the border widths. Overflowing radii scale by one common factor (`ConstrainRadiiForQuadSize` replaces `ClampRadiiForQuadSize`). Images fit and clip in the content box, and `object-fit: none` is centred. The pinned shader can't draw a radius past half a side; R16 fixes that.
- [31 - TypeAhead helper](issues/31-typeahead-helper.md): `gpui.TypeAhead`, a port of Blink's type_ahead.cc. It has a 1 s timeout, first-letter cycling, matching from the selection with wrap-around, and case/accent folding (precomposed Latin only, not full ICU). The clock is injectable.
- [47 - Preferred frame interval](issues/47-preferred-frame-interval.md): `WindowOptions.PreferredFrameInterval` / `Window.SetPreferredFrameInterval`. Like Chromium, only full and half rate exist: half rate when interval > 2×vsync − 0.5 ms. The pacer grants a half-rate window every other slot, using a measured median vsync.
- [02 - Wheel page-scroll setting and capture release](issues/02-wheel-page-scroll-and-capture-release.md): WHEEL_PAGESCROLL becomes a `ScrollDelta` Pages variant, resolved at the scroller with Chromium's page step; mouse capture is released only when no button is held.
- [03 - Missing cursors and frames for hidden windows](issues/03-cursors-and-hidden-window-frames.md): grab, grabbing, copy and context-menu are runtime-built 32x32 monochrome cursors (Windows has no system ones); minimized or DWM-cloaked windows keep their frame demand pending until visible. Ordinary occlusion is not detected.
- [04 - CSS shadow and blur geometry](issues/04-css-shadow-and-blur-geometry.md): `Scene.PaintBoxShadow` (the Style path) uses σ = blur/2, grows spread corner radii with CSS's corner-correction rule, and paints the first shadow on top. Shadows and the ring paint inside the filter group, whose bounds are the element's ink bounds. Measured: the pin's filter and backdrop σ already equal the CSS radius, because the blur runs at half resolution. The spec's D8 note was wrong; no change was needed. shadow-backdrop's pixels wait on rev 15.1.
- [13 - Key code and location, with Shift kept](issues/13-key-code-and-shift.md): `Keystroke.Code` and `Location` come from the scan code (Chromium's dom_code_data table). Shift is kept on shifted keys, so `ctrl-shift-]` and `ctrl-}` both match. Code-less keystrokes still match exactly. `WithSimulatedCode` gives simulated input and replay the platform's spelling. The harness logs code and location, and the recorder sets CDP's code, VK, location and keypad flag.
- [41 - Filters, object-position and pixelated images](issues/41-filters-object-position-pixelated.md): the CSS colour functions use Chromium's matrices in sRGB, and a chain composes into one 4x5 matrix plus one blur, painted as one group. Also `ObjectPosition`, `ImageRendering` pixelated (point sampler) and Tailwind classes. Colour filters are no-ops on the GPU until rev 15.1 (the uniform-upload bug); those fixtures set `SkipPixels`, a new harness field.
- [06 - Text style quick fixes](issues/06-text-style-quick-fixes.md): text-transform, ligatures off under letter-spacing, Chrome underline geometry (`AutoThickness`), the line-clamp ellipsis, numeric-variant classes, generic families (sans/serif/mono to Arial/Times/Consolas) and grayscale AA on non-opaque windows. No native change. Chrome's whole-pixel baseline is a known residual.
- [65 - TSX release bundling](issues/65-tsx-release-bundling.md): `go generate` runs `cmd/tsxbundle`, which writes `ui.tsxbundle.{js,go,_test.go}` with an embedded `script.EmbeddedBundle`. The generated test catches stale bundles (`CheckFresh`). Compile errors report the .tsx file:line. The release binary links goja but not esbuild (`examples/tsx-hello`; +12.4 MB stripped).
- [11 - Pointer capture and local position](issues/11-pointer-capture-and-local-position.md): `Window.CapturePointer` now retargets like Chromium. The capture is pending until the next pointer event; `OnGotPointerCapture`/`OnLostPointerCapture` fire; moves go to the captured chain; the capture is released after the ups, with boundary events last. A foreign WM_CAPTURECHANGED dispatches `PointerCancelEvent`. Mouse events gained `LocalPosition(hitbox)`. The harness gained pointerdown/move/up and got/lost capture kinds (`fixtures/capture`). Click is still not instrumented: the pin fires click before the up listeners.
- [33 - position: static opt-in](issues/33-position-static-opt-in.md): `PositionStatic`, `Static()` and the Tailwind `static` class. The default stays Relative until 76. Taffy has no static value, so the record maps static to Relative with the insets zeroed. The containing block is decided Go-side: a scope stack in the request-layout walk (`gpui/containingblock.go`), where static parents defer their absolute children to the nearest positioned ancestor. Custom containers opt in with the new `Window.RequestContainerLayout`; Anchored, Deferred and custom elements don't use it yet. The lint is `gpui.LintAbsoluteUnderStatic`. Fixture: `position-static`.
- [25 - Anchored to an element](issues/25-anchored-to-element.md): `AnchoredElement` gained `AnchorTo(id)` and `AnchorBounds(*Bounds)`; `Side`, `Align` and `Gap`; `TryFallbacks(AnchorFlipBlock, AnchorFlipInline, AnchorShift)`, where the base placement wins when it fits, as in Chromium; `Margin`; and `HideWhenAnchorClipped()`, which skips paint but keeps layout. Anchors come from a per-frame registry of named divs, filled only once a window uses AnchorTo. Base's tooltip now uses it. Fixtures: `anchor-sides`, `-flip`, `-shift` and `-hidden`. The recorder now waits two animation frames before reading. Gaps: cell anchors have no clip rect, hidden popups keep their hitboxes, cached views lag one frame, and flip plus shift clamp the base side. Anchored is not a containing block for 33's `Static()`.
- [30 - Spellcheck service](issues/30-spellcheck-service.md): `gpui.SpellcheckService` (`App.Spellcheck()` / `SetSpellcheck`) runs the Windows ISpellChecker COM API on its own goroutine, locked to an OS thread in an STA, like Chromium's COM STA runner. A newer request per key supersedes older ones, results post back to the UI thread, and a `SpellChecker` seam allows fakes. Base inputs opt in with `InputState.Spellcheck(true)` and draw red wavy underlines. It is off by default, and masked inputs never check. Gaps: one language per check, and no suggestion UI.
- [29 - Forced-colours pass](issues/29-forced-colors.md): when Windows high contrast is on, style resolution maps colours the way Chromium's AdjustForForcedColorsMode does. Text, borders, ring and decorations become CanvasText; backgrounds become Canvas with their alpha kept; gradients and box shadows are dropped. It follows the OS, and the state is cached per preference version (11 ns, 0 allocs when off). Opt-outs: `ForcedColorAdjustNone()` / `forced-color-adjust-none` per element, and `App.SetForcedColors(&ForcedColorsState{Active: false})` for the whole app. The harness gained `Fixture.EmulatedMedia`, `ComputedScript` and `Configure`. No UA-sheet roles (links, inputs) yet.
- [77 - R15.1 native follow-up](issues/77-r15-1-native-follow-up.md): native revision 151 (= 15.1), DLL `ef337ad3…`. The uniform upload is fixed, so colour filters and the backdrop crop work. Chains now apply one matrix per function with a [0,1] clamp between them, as Chrome does; the filter record is 780 bytes and holds up to 8 functions. Synthetic italic is an exact −0.25 shear, and text-wrap: nowrap is wired. filters-colors and filters-chain are pixel-exact, and shadow-backdrop is back. Open: the partial-region backdrop crop zooms (for R16). The other text-run fields and the baseline are blocked behind the pinned Parley/Taffy seams (recorded per field), so 42/43 need a plan.
- [12 - Click on the common ancestor, activation and focus-visible](issues/12-click-activation-focus-visible.md): click goes to the common ancestor of the press and release (through the armed chain, so a stopped mousedown or a block-mouse overlay still blocks it) and fires after mouseup and the capture release. Enter activates on key-down; Space holds :active and clicks on key-up; the keyboard click bubbles. :focus-visible follows the focus origin (mouse focus shows no ring, Tab does, and modified keys don't count). Mousedown focus no longer reports defaultPrevented. The harness gained KeyDown/KeyUp half-press steps. Gaps: any OnClick element counts as activatable; no text-input always-ring.
- [34 - position: sticky](issues/34-position-sticky.md): `PositionSticky`, `Sticky()` and the `sticky` class. Sticky lays out in flow (Relative, insets zeroed); the offset is computed at prepaint with Chromium's per-axis clamp to the containing block, so a scroll needs no re-layout. Sticky children paint after their in-flow siblings, and sticky is a containing block for absolute children (33's scope). List-header hook: `WithStickyScrollContainer` + `StickyOffset`. Fixtures: `sticky-*` (5). Gaps: no root/document scroller, inline sticky doesn't stick, OverflowHidden isn't a sticky container (36), float32 offsets, and key/hitbox order follows the paint reorder.
- [28 - Text scale to rem, caret blink and highlight colours](issues/28-text-scale-caret-highlight.md): rem = 16 × the Windows text scale by default (D11), with live reflow on a settings change; the app opts out with `SetRemFollowsSystemTextScale(false)` or pins it with `SetTextScale`. Caret blink uses the system rate, and 0 means a steady caret. Selection uses the system Highlight wash plus HighlightText (`App.SelectionColors`), and Base inputs and selectable text default to it. Everything is cached per preference version. Gap: rich-text TextView selections keep the theme wash (19/20).
- [44 - Transition style property and the core motion engine](issues/44-transition-property-and-core-motion.md): the timing/easing/keyframe engine moved from Base into gpui (`gpui/motion*.go`); Base keeps aliases plus springs and MotionTransform. `Styled.Transition` animates width/height (px/rem), opacity, background and border through a per-element style diff at the div's style resolutions, with Chromium's last-rule-wins and reversing-shortening rules. It needs an element ID, requests frames only while running, and reduced motion completes immediately. The harness gained `Wait(ms)`: the recorder seeks the Web Animations timeline (virtual-time budgets don't drive CSS transitions in --headless=new), and the replay calls AdvanceClock. Gaps: no property-only frames (60), no transforms (56), and percentage/auto sizes change discretely.
- [63 - TSX surface, generated .d.ts and check command](issues/63-tsx-surface-types-check.md): `internal/tsxgen` extracts the TSX surface from the engine's own code (jsxElement, parseStyle, eventObject, host globals, the class tables) and `cmd/tsxdtsgen` writes `gpui/script/types/gpui-script.d.ts`. Drift tests fail in both directions without tsc. `cmd/tsxcheck` runs tsc (found through `GPUI_TYPESCRIPT`, node_modules, npm global or PATH; nothing installed), and `script.WithTypeCheck` type-checks off-thread after each reload. `className` is typed string (unions of space lists are too slow for tsc). **Any ticket adding a class or style key must run `go generate ./gpui/script/types`.**
- [36 - Display modes, overflow: auto and scrollbar gutter](issues/36-display-modes-and-overflow-auto.md): display contents (children spliced into the parent at request layout, no box), inline-block/inline-grid (atomic inline boxes) and flow-root. `OverflowAuto` shows a classic 15 px scrollbar (calibrated to headless Chrome) only while an axis overflows, settling one frame later; `scrollbar-gutter: stable` reserves the gutter. Hidden/auto overflow are sticky scroll containers now (closes 34's gap). The classes `contents`, `inline-block`, `inline-grid`, `flow-root` and `scrollbar-gutter-stable` were added, and `overflow-auto` is real auto now. Gaps: overflow: scroll still draws no scrollbar (pin), contents at the window root takes only its first child, no visible→auto cross-axis rule.
- [32 - Text min-content wraps](issues/32-text-min-content-wraps.md): text min-content wraps at every break opportunity (wrap width 0) in the Text leaf, StyledText and the inline paragraph, so text in a flex row shrinks and wraps (D2). The measure cache is keyed by sizing mode, and a max-content query never reuses a wrapped shape. Fixture: `mincontent-wrap`. Gaps: nowrap keeps min = max; line-clamp still caps the wrap-0 rows.
- [14 - Core Tab navigation, focus fixup and Inert](issues/14-core-tab-navigation-and-inert.md): `TabStopMap` follows HTML order (positive tabindex ascending, then 0 in tree order; negative never). Tab past the last stop blurs instead of wrapping, the way Chrome passes focus out. A focused element that is removed, hidden or inert blurs at frame end, keeping the navigation starting point. Mouse focus walks the press's ancestors, and a press on empty space blurs. `Inert()` suppresses the subtree's listeners, hit testing and a11y while it still paints. Body-focused keys reach the root's listeners.
- [17 - Context-menu event](issues/17-context-menu-event.md): `DivElement.OnContextMenu` / `ContextMenuEvent`. A right-button release fires it after the whole up tail; the Menu key fires on key-up and Shift+F10 on key-down, at the focused element's centre (Windows arms). The recorder sends rawKeyDown for text-less keys.
- [18 - IME composition events](issues/18-ime-composition-events.md): `IMECompositionHandler` (an optional InputHandler extension) gets CompositionStart/Update/End in Chromium's order around the text mutations, and `KeyDownEvent`/`KeyUpEvent.IsComposing` is stamped at dispatch. `Window.SimulateIMEComposition` is the test seam. The harness gained `ImeSet`/`ImeCommit` steps (CDP imeSetComposition/insertText) and `data`/`isComposing` transcript fields. Gaps: a real IME's VK_PROCESSKEY keydowns stay untranslated (the TSF slice), and there are no div-level composition listeners or beforeinput/input yet.
- [66 - Dev command: TSX reload and Go restart with state](issues/66-dev-command.md): `cmd/tsxdev` supervises an app built with `-tags dev`. It polls the package by content hash with a debounce: a .tsx save reloads in place (~250 ms), and a .go save builds first, then saves state, restarts and restores (~4-5 s warm). The handoff is the `GPUI_DEV_STATE` JSON file plus `reload`/`save` lines on stdin; it carries keyed script state, the shared store and window bounds. Window placement fix along the way: `SetBounds` now lands the exact client origin (measured non-client offsets), so `SetBounds(Bounds())` is a no-op (winhostspec bounds_test).
- [21 - Top layer and light dismiss](issues/21-top-layer-and-light-dismiss.md): `OverlayHandle` (Show/Hide/Toggle/OnToggle) and `TopLayer(handle)` (Kind popover/manual/hint/modal, Invoker, Backdrop, PassThrough), one ordered top layer per window. Light dismiss runs in the click dispatch with Chromium's press/release pair rule; the nearest open popover ancestor vs the invoker's popover decides, and everything above is hidden. The show rules close non-ancestors. Base's popover moved onto it, fixing the nested-dismiss fault. Anchored is now a containing block (RequestContainerLayout). The harness gained `toggle` entries. Gaps: the show rules run a frame late, there is no position: fixed (35), and Escape/modal are 16/22.
- [07 - Scroll range and pixel rounding](issues/07-scroll-range-and-pixel-rounding.md): the scroll range comes from the layout record (Taffy's content size plus trailing margins); vertical padding % resolves against the width; border widths floor in CSS px (Chromium ClampLineWidth: sub-1 keeps 1). The harness gained `Fixture.Scale` and `parity.Script`.
- [46 - Scroll anchoring](issues/46-scroll-anchoring.md): Chromium's anchor selection (the first rect intersecting the scrollport, descending past partial boxes) keeps visible content in place when content is inserted above. The identity is the element id path plus occurrence. Gaps: no overflow-anchor: none, O(subtree) walk, horizontal-tb only.
- [26 - Edit actions and the HTML clipboard](issues/26-edit-actions-and-html-clipboard.md): core `Copy/Cut/Paste/SelectAll` on Chrome's Windows key table run as the first default-action arm (not during IME), through the `EditActionHandler` seam with Chrome's copy/cut/paste/beforeinput/select order. CF_HTML read/write (`ClipboardString.HTML`), `App.OnClipboardChange` (WM_CLIPBOARDUPDATE), and OpenClipboard retries. Ctrl+C/X/V can't be recorded headless (the Windows alternates are used instead).
- [38 - White-space collapse, tab size and em letter spacing](issues/38-white-space-and-tracking.md): `gpui/white_space.go` collapses whitespace like CSS (normal/nowrap/pre-line, plus Pre/PreWrap values) across inline boundaries, with a caret byte map (Chromium OffsetMapping semantics) so TextLayout positions answer in source offsets. Tabs under pre use 8-space browser stops (`TabSizeSpaces`), and `LetterSpacingEm` adds em tracking. The classes `tracking-*` and `whitespace-pre|pre-line|pre-wrap` were added. Base's text stays verbatim (pre-wrap/pre). Gaps: ZWSP/East-Asian segment-break rules, and Base flow tabs measure with the old stops.
- [48 - Outline and the default focus ring](issues/48-outline-and-default-focus-ring.md): `Style.Outline` (width/kind/colour/offset) paints above the content; the kinds are auto, none, solid, dashed and focus-ring. The UA `:focus-visible` rule paints Chrome 155's single 2px #101010 ring (radius plus offset; Highlight under forced colours). Classes: outline, outline-<n>, outline-offset-<n>, outline-<color>, outline-none, outline-dashed. Fixtures that pin outline: none carry `.OutlineNone()` twins. Gaps: no dotted/double (scene borders are solid/dashed), and outline isn't transitionable.
- [68 - Display codemod](issues/68-display-codemod.md): `cmd/displaycodemod` (go/parser + go/ast, no new dependencies) inserts `.Flex()` right after every `gpui.Div()`/`Img()`/`Canvas()` whose method chain never sets display, so any later display choice still overwrites it. Explicit forms: `Flex/Block/Grid/Inline*/Contents/FlowRoot/Hidden/Display` and `Class` literals with an unprefixed display class. Dry-run diff by default, `-w`, `-check`; idempotent, and a sample package lays out identically before and after. Dry run: 235 files, 1341 insertions (gpui 77 files, mostly tests; base 74; examples 25; internal 59). TSX needs nothing: every `<div>` lowers through the one `gpui.Div()` in gpui/script/lower.go. Gaps: `Svg()`, text and the lists aren't chain roots (71 pins them in their constructors).
- [69 - Codemod applied in gpui-go](issues/69-display-codemod-gpui-go.md) and [70 - Codemod applied in Base, zterm and the gallery](issues/70-display-codemod-base-and-apps.md): `displaycodemod -w ./...` pinned 1,344 `.Flex()` calls in 236 files (gpui 77, base 75, examples 25, internal 59, including 38 parity fixture views), and `-check` stays at 0. The tool skips generated files. The TSX `<div>` lowering in gpui/script/lower.go is pinned with a note for 71. No fixture records changed, and the zterm/gallery captures are identical apart from the animation noise that also shows between runs of the same code. Left for 71: `Svg()`, `Text`, `NewStyledText`, `List` and `UniformList` aren't chain roots.
- [71 - Default display is block](issues/71-flip-default-display-block.md): `DefaultStyle()` is `DisplayBlock` (D6; a recorded divergence from the pin's Flex). A plain div stacks its children, its auto width fills the container, and text forms a paragraph (fixture `display-block` matches Chrome 155). Leaf constructors pin their display (`Svg`, `Text`/`StyledText`, `List`, `UniformList`, `TextSelectionLayer`, the surface element). A TSX `<div>` follows block, while the `<text>` sugar keeps flex. 138 fixture-view pins whose pages use plain block divs were removed. `displaycodemod` now acts as a lint: it pins only chains whose flex/grid-container vocabulary would go inert under block. Along the way the paragraph measure cache became three sizing-mode slots. Gaps: margin collapsing isn't verified, there are no floats, and no full anonymous-box model.
- [72 - Base overlays rebuilt on core primitives](issues/72-base-overlays-on-core.md):
  - Base's dialog, alert dialog and sheet use `Window.ShowModal` with a pass-through TopLayer entry (ClosedBy mapped from the close options; Escape through the entry's close watcher, whose OnCancel vetoes).
  - Select, combobox and popover close on Escape through close watchers.
  - Tooltip uses the core tooltip hook, and popups are positioned by `gpui.Anchored`.
  - Deleted: base/focus_trap.go, base/positioner.go, the popover tracking list, the five Escape bindings and Base's Tab bindings (Tab is the core default; the modal's inert outside replaces the trap).
