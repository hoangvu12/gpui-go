# Module and native distribution contract

Status: documentation selection for [Define module boundaries and native distribution](../.scratch/gpui-core/issues/08-define-module-and-native-distribution.md), 2026-10-04. This document integrates the [distribution research](../research/18-module-native-distribution.md) with the accepted authoring, ownership, layout, Windows and renderer contracts. It specifies future artifacts and tooling; none has been built, loaded or published.

## Module and ownership boundaries

Keep one local Go module, `gpui-go`, with the existing `go 1.27.0` floor. The future root package is named `gpui`; a directory named `gpui` is not an additional required import level. The public module path and project license remain undecided until publication work. The existing public `authoring` package remains usable independently. Do not introduce a root/authoring import cycle or duplicate style identities: put shared authoring definitions below the root and expose compatible aliases/adapters where needed, subject to the authoring-signature gate.

| Boundary | Responsibility |
|---|---|
| Root `gpui` and existing `authoring` | Accepted entities, elements, styles, events/actions, typed access and application/window APIs |
| Root `internal/abi`, `internal/nativeloader` | Private records, validation, artifact identity, loading and fixed callback registration |
| Internal layout/text/scene/platform adapters | Convert Go contracts to service operations; own no second application runtime |
| Internal Win32 host | Foreground dispatch, HWND ownership, input and Go application integration |
| Internal native artifact package | Windows AMD64 binary bytes, exact manifest and notices, selected by build constraints |
| Maintainer native workspace and generators | Locked Rust extraction, ABI bindings, shaders and release artifacts; absent from ordinary app compilation |
| Future pure-Go packaging command | Application manifest/resource preparation, artifact inspection and explicit sidecar export |

Root-level `internal` makes these implementation packages importable only from the module's parent import subtree under [Go's internal-package rule](https://go.dev/cmd/go#hdr-Internal_directories). They must not appear as types that external custom elements need to name. Public contracts or narrow internal interfaces carry callbacks across package boundaries without dependencies back into root implementation types. Base remains a future consumer of the public API.

Framework ABI/style generators are maintainer tools with checked-in, reproducible outputs. App authors do not need generation for fluent components. Resource preparation for an application executable is a separate explicit operation; `go build` does not run `go generate` automatically.

## One native artifact with logical services

Select one maintainer-built Windows AMD64 Rust `cdylib`, with separate private service tables for layout, text/rasterization, scene/renderer/capture, and accessibility/COM integration. Their logical ownership remains exactly as selected in the [layout](layout-contract.md), [Windows](windows-platform-contract.md) and [renderer](renderer-contract.md) contracts. Consolidation changes distribution, not who owns the application, HWNDs, elements or foreground dispatcher.

One exact artifact removes cross-DLL allocator and service-version combinations from the initial target. Separate DLLs remain an alternative if measured build/distribution needs justify them later. Different dependency licenses do not by themselves require separate binaries, and DLL separation inside one process does not provide crash isolation. No size, memory or compilation-speed benefit is claimed. Individual services initialize when needed; loading the file must not eagerly create windows, COM apartments, devices or font databases in `DllMain`.

Also include native CPU image decoding and SVG parsing/rasterization. The [asset snapshots](../evidence/distribution/manifest.json) and [existing lockfile](../evidence/windows-platform/Cargo.lock) pin `image` 0.25.10 (the workspace's 0.25.1 is a version requirement), `resvg`/`usvg` 0.48.1 and the actual GPUI adapters. Retain the effective codec/features graph; advertised filename extensions alone are not proof that every decoder is built or every animation path is used.

Go owns the asset registry and duplicate-path policy, preloaded/on-demand sources, file/URI resolution, injected HTTP client, load/error state, image-cache identity, animation scheduling and scoped task completion. Native services receive copied bytes and explicit decode modes, and return owned frame records with dimensions, channel/alpha meaning, rational delays and image scale. Preserve the difference between `Image::to_image_data` and resource image loading: the latter has an animated WebP path, while the former routes WebP through static decode. GIF frame-error handling, EXIF orientation and channel conversion remain source-specific. Do not unify the modes by changing observable behavior. Zero-frame and malformed input cases must retain their source/error contracts.

The SVG service owns parsed native trees and the pinned font-selection/raster algorithms. Preserve size modes, smoothing scale, raster dimension limits, icon alpha-mask output and the exact conversion from premultiplied RGBA to straight-alpha BGRA, including the pinned unpremultiply arithmetic. Go resolves asset bytes; native workers never invoke arbitrary Go asset closures. Preserve lazy bundled-font resolution with an explicit native request/resume protocol: on first need, return a needs-assets status with an owned suspended request, let Go task orchestration resolve/copy the known paths' available bytes, then resume using the same logical renderer/font snapshot. CPU decoding need not run on the foreground thread. Record missing fonts and cache lifetime as the source does; do not load every on-demand asset at application initialization. Dispose partial parses and responses through task/native completion ownership. Compare this adaptation against source traces for lazy loading, concurrency, cancellation and renderer replacement.

The [HTTP interface](../evidence/distribution/crates__gpui__src__http_client.rs) is an injected asynchronous GET accepting a URL and `follow_redirects`, returning status/body or an error. Preserve the default `NullHttpClient` failure and the explicit blocked-client permission error. Resource URI loading requests redirects and maps non-success status to the existing image error, including the first body line. A Go task/context adapter can express cancellation under the runtime contract, but must not silently replace the default with `http.DefaultClient`. Any convenience `net/http` adapter is explicit caller configuration with its own redirect/timeout policy. No HTTP library or TLS stack is added to the native artifact for this seam.

## Consumer delivery

Ship the exact prebuilt DLL and manifest as ordinary files inside the Go module, embedded only by the Windows AMD64 artifact package. After dependency acquisition, building and running needs Go plus those already supplied artifacts, `CGO_ENABLED=0`, and no Rust, C, Windows SDK or shader compiler. Module checksums cover released module content; local `replace` directories are local inputs and are not magically authenticated by a remote checksum database. Native hashes remain checked in both cases. [Go embedding](https://pkg.go.dev/embed) and the [module zip rules](https://go.dev/ref/mod#zip-files) establish the mechanism, not proof of the proposed build.

Keep both compressed and expanded module zip size within Go's 500 MiB limits. Release validation must inspect the actual zip: the DLL must contain binary bytes, not a Git LFS pointer; embedded assets and notices must be present. Symbol files and maintainer/oracle build outputs belong in separate release artifacts. If the native payload exceeds module limits, revise the artifact distribution decision before release rather than silently adding a runtime download. No artifact size has been measured.

Default delivery embeds the binary and materializes it on first application startup. Also support an explicitly configured absolute bundle directory containing the exact expected bytes, for offline installation and environments that prohibit writable executable caches. An export command can copy the embedded artifact and notices into that bundle. There is no automatic network fetch, compiler fallback, unversioned system installation, or ambient `PATH`/environment override. Selecting a bundle is deliberate application configuration and never relaxes identity checks.

## Materialization and loading

The normal location is below `os.UserCacheDir()/gpui-go/native/windows-amd64/<full-sha256>/`; the DLL basename also includes its full hash. Keep extraction out of the module cache and application source tree. A read-only installation directory is harmless when the per-user cache is writable. With no usable cache, require the explicit verified bundle and return a typed initialization error; do not fall back to an uncontrolled shared temporary directory.

Use a restricted per-user directory and a cross-process lock for the artifact. Under that lock, inspect any existing final file; otherwise write a uniquely named staging file in the same protected directory, verify its complete length/hash, flush and close it, then publish and verify the final file before use. All framework loaders participate in this lock. A crashed writer's incomplete bytes are never accepted simply because a destination exists. A corrupt final file produces an error; do not overwrite a possibly mapped DLL. Publication and crash recovery require Windows execution tests: [os.Rename](https://pkg.go.dev/os#Rename) is not an atomicity guarantee on Windows.

Resolve the final path and reject unexpected reparse redirects or locations outside the configured directory. Open the selected DLL for read with sharing that denies write/delete, hash that open file, and retain the verified-file handle across loading; retain the protection for the module's process lifetime. This is a design to test against real filesystem/loader behavior, not a claim of protection from a process running with the same authority or an administrator.

Call explicit `LoadLibraryExW` with the absolute path and `LOAD_LIBRARY_SEARCH_SYSTEM32` for dependencies, then obtain the required exports. The initial single artifact has no private companion DLL imports. If future artifacts need them, revise the manifest and use a verified artifact directory plus `LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR`; do not add global DLL search paths. Bare `NewLazyDLL` discovery is not this policy. Windows still applies its loaded-module/API-set/system rules, so these flags are not universal in-process dependency isolation. See [LoadLibraryExW](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-loadlibraryexw) and [DLL search order](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order).

Inspect the PE machine type before load and report wrong architecture explicitly. Required exports, ABI tables and compiled capabilities must validate before initializing a service. Missing bytes, inaccessible storage, hash mismatch, architecture mismatch, OS load failure, incompatible ABI and missing required capability are distinct errors carrying expected identity, actual identity when available, path and native error code. They never trigger another layout engine or a blank successful renderer.

## Exact artifact identity and private ABI

Each Go release embeds one authoritative manifest and one exact accepted DLL hash for the initial target. A bundle-local manifest cannot authorize a replacement hash. Artifact identity includes the CE pin `254b5dbd47cbb5acbcc5bbdcbb322a339276c88a`, bridge source/patch revision, target, private ABI schema identity, service table versions and compiled feature set. Changing any native bytes creates a new artifact identity, even when public Go APIs are unchanged.

Use a fixed bootstrap export with integer/pointer arguments and a caller-sized identity/service-table record. The loader checks record sizes before reading fields, validates required table lengths and functions, and rejects unknown required capabilities. ABI major mismatch fails; additive minor extensions are meaningful only with adequate record sizes and an explicitly accepted artifact. A higher minor version alone never permits loading an arbitrary newer DLL. Changes to existing field interpretation, enum/tag meanings, callback contracts or ownership require an incompatible schema revision.

Records use specified widths, offsets, alignment, padding, tags, lengths and float bit encodings. No Go/Rust slice, string, enum, boolean, closure, interface or struct layout is assumed to be the wire format. Export and callback signatures use machine-word scalars and record pointers. Go's AMD64 procedure call path does support floating-point arguments/returns; avoiding them here is a private ABI simplification, not a platform impossibility. Use matching Windows calling conventions and fixed trampolines with generation tokens; callback allocations must not grow per entity/frame. [Go syscall facilities](https://pkg.go.dev/syscall#NewCallback) provide mechanisms, not bridge execution proof.

Synchronous borrowed Go buffers contain no Go pointers and remain pinned/alive for the call. Native work copies everything retained asynchronously. Native-owned results are copied or held with an explicit native lease and freed by their owning service. Rust catches unwind-enabled panics before returning; Go callback trampolines recover/latch failures and propagate only after returning to ordinary Go. An allocation failure, process abort or memory fault is not promised recoverable. Inspect the explicit status before interpreting Windows last-error state.

## Maintainer builds and provenance

Build for `x86_64-pc-windows-msvc` with `-C target-feature=+crt-static` and bridge profiles using `panic = "unwind"`. Audit native dependency build scripts for matching CRT settings; compiler flags alone are insufficient proof. Static CRT selection is supported by the [Rust linkage reference](https://doc.rust-lang.org/reference/linkage.html#static-and-dynamic-c-runtimes). Do not inherit an aborting workspace release profile. Catch panics inside each export; do not unwind through Go or another foreign frame.

The selected payload must not require a separately installed VC++ redistributable or consumer toolchain. Inspect actual normal, delay and dynamically loaded imports on the built artifact. Windows system components remain OS dependencies. Shader compilation is maintainer work: preserve the selected Rust/WGSL/Naga/HLSL/DXBC pipeline and embed resulting DXBC. A shader compiler accidentally retained as a runtime requirement fails release validation.

The artifact manifest records source revisions and patches; exact Rust/MSVC/SDK identities and target; Cargo lock hash, package checksums and effective target feature graph; CRT/panic/linker flags; ABI generator/schema hashes; shader inputs/compiler flags/output hashes; all artifact lengths/hashes and imports; capability inventory; build command/environment; and complete dependency/asset notices. Preserve source and transformation provenance separately from reproducible-build claims. Two builds have not yet demonstrated byte reproducibility.

The pinned GPUI manifest declares Apache-2.0; Taffy, text and accessibility dependencies carry their own notices, as documented in the [research](../research/18-module-native-distribution.md). Account for the actual extracted files and full transitive graph, shaders, fonts and other assets; a short top-level license table is not the complete inventory. Ship corresponding license/NOTICE material with embedded and exported artifacts. Do not redistribute installed Windows fonts just because a fixture uses them, or infer a license for new gpui-go code from dependency metadata. Publication waits for a complete inventory and project licensing decision.

## Application DPI resources

Offer a pure-Go resource preparation command that writes the consumer main package's architecture-specific `.syso` containing an application manifest with PerMonitorV2. It must preserve explicit application resource settings and report conflicting manifests instead of silently overwriting them. The pure-Go [go-winres approach](https://github.com/tc-hib/go-winres) demonstrates the resource mechanism; pin and record the chosen generator dependency during implementation. Once generated and included, ordinary `go build` needs no resource compiler. Inspect the final executable's manifest, not just the input XML or a DLL resource.

For ordinary development without an embedded manifest, perform guarded `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` before framework OLE/HWND initialization. First inspect existing awareness; an already-correct manifest needs no second set call. If another component has fixed an incompatible process/thread mode, return a clear initialization error rather than continuing with virtualized coordinates. The foreground thread must remain in the intended mode. The manifest is the preferred shipped-app path; both paths require actual validation under [Microsoft's DPI setup rules](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process).

## Capability coverage and lifetime

The initial artifact targets the recorded Windows AMD64 PC. ARM64, 386, older Windows and other operating systems are not advertised as supported. An unsupported target fails clearly at build or host initialization; pure authoring-only utilities may remain portable. Do not equate a successful cross-compile with platform support.

Required compiled services include pinned Taffy defaults, the full selected text/raster stack, image/SVG processing, AccessKit/COM adapters and native D3D11 scene/atlas/shaders. Capture is a required compiled baseline capability, with runtime OS/user/device availability reported separately. Both DComp and DComp-disabled HWND modes are supported contract paths. Capture obtains `IDXGIDevice` from the actual D3D11 device and checks errors, independent of the optional composition member. Wgpu/custom-GPU/external cross-device surfaces are not silently supplied by this artifact; preserve the renderer contract's explicit capability accounting and review reference applicability before claiming full core parity.

The conformance inventory must enumerate all source features, including inspector/test support, assets/images/SVG, HTTP-client injection, platform credentials/dialogs, hot-patching and profiling hooks. Every row needs a source reference, Windows applicability, implementation owner and planned evidence or an explicit reviewed exception. An omitted row is not an exception. Artifact grouping cannot narrow the full-core destination.

Keep successfully loaded service code resident for the process lifetime. There is no normal `FreeLibrary` or debug hot-unload path in the initial design. Logical services, buffers, engines, windows, COM objects and GPU resources still close according to their contracts; residency is not permission to leak all service state. Native provider references, callbacks and submission/capture obligations can outlive a window. Quarantined work retains its dependencies until safe retirement or process exit; module residency does not itself establish GPU completion. Preserve foreground and apartment release order, and continue terminal acknowledgment handling after application scopes close.

## Required evidence before delivery

Run a clean Windows Go-only build with `CGO_ENABLED=0`, then actual DLL calls, callbacks, text, layout, drawing and shutdown. Verify offline module/bundle operation, final PE resources/imports, fixed callback count, full record layout, panic containment and GC under synchronous calls. Exercise concurrent first extraction, killed writers, read-only storage, corrupt bytes, redirects, wrong machine type, wrong service tables, missing features, ABI mismatch and OS load failure. Exercise provider references and hidden/in-flight/quarantined GPU work after window closure. Check actual runtime capability records against the built manifest.

These checks belong to the selected [conformance contract](conformance-contract.md), supported by [research](../research/19-conformance-update-policy.md). Native/delivery checks are all unexecuted. No bridge implementation, installation, benchmark or publication occurred for this decision. The later bounded authoring-signature task passed under user-installed Go 1.27.1; it does not verify this native boundary.
