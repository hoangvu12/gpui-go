# Windows core conformance inventory

Status: selected family inventory, 2026-10-05. CE reference: `254b5dbd47cbb5acbcc5bbdcbb322a339276c88a`. This is a coverage assignment, not an executed capability ledger. All framework/native rows below are **planned**. The bounded [signature evidence](../evidence/authoring-signature-validation.json) alone has passed; it does not prove runtime rows. The [conformance contract](conformance-contract.md) defines comparisons, profiles, fixture schemas and evidence states.

## Profiles and accounting

- Native Windows default effective feature graph plus selected capture is the first artifact/reference profile. Debug/test/inspector behavior is recorded separately, including plain debug assertions.
- Alternate wgpu/custom-GPU and hot-patching/profiling have explicit applicability rows below. Their absence from the selected artifact is not approval to drop an applicable core operation. Reference unsupported/no-op results need source evidence and fixtures.
- The first implementation ticket enumerates every public export and platform/window/text/element operation into a versioned ledger with source/profile, Windows applicability, owner, fixture IDs, result and exception/adaptation provenance. Family rows are not a substitute for that enumeration. Unexpected work is ticketed before its family can close.
- Full-core acceptance requires every applicable row accounted for and its required gates passed; blocked environments and proposed exceptions remain visible. No release/parity claim may count missing rows as passed.

## Explicit remaining execution questions

Oracle recordings and reference build identities belong to the first slice. Combined-artifact size is measured at the first native build and again for final delivery. Caret coordinate convention is established by the nonzero-origin IME reference fixture, not a guessed comment interpretation. Actual driver/MSAA/capture/IME/UIA behavior and visual tolerances require on-device evidence. JSON-schema support and accessibility ID determinism have explicit implementation/test owners. None is reported as passed by this plan.

Initial Go adaptations are the selected scope/borrow/cancellation/payload rules, dynamic child diagnostics, explicit action cloning, native completion, same-device capture and lazy font request/resume. Each needs a fixture-linked adaptation record. There are no blanket exceptions for optional features, missing Windows operations or failed tests. A source contradiction reopens the affected Wayfinder decision with a reproducer.
