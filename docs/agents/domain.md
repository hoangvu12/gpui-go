# Domain documentation

This project uses one root [CONTEXT.md](../../CONTEXT.md) glossary and ADRs under `docs/adr/`.

Before exploring a domain question, read the glossary and any relevant ADRs. If ADRs do not exist, proceed; create them only when there is a decision worth recording.

Use the glossary's canonical terms. Capture resolved terminology as it emerges. Keep implementation plans and session state out of the glossary: project intent lives in [PROJECT.md](../../PROJECT.md), research in `research/`, and Wayfinder decisions in their tickets.

Offer an ADR only for a decision that is hard to reverse, surprising without its context, and the result of a real tradeoff. Flag conflicts with existing ADRs explicitly. Link to canonical decisions instead of duplicating their rationale.
