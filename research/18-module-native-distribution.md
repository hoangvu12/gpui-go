# Module boundaries and native distribution

Research date: 2026-10-04; revised after main review. Proposal for [ticket 08](../.scratch/gpui-core/issues/08-define-module-and-native-distribution.md); main owns review and this invocation's resolution. Local module `gpui-go`; no public path, branding, or module-license decision is made here (dependency licenses below inform notice obligations only, not the module's own license). No consumer build, native build, install, or publication ran. Inputs: the four selected contracts, pinned CE sources, and primary Go/Windows/Rust documentation.

## 1. Go module and package boundaries

Module `gpui-go` with the **root package named `gpui`** (importing `gpui-go` yields package `gpui` — the authoring contracts' single-package public surface), the existing **public `authoring`** package (`gpui-go/authoring`), and **root-level `internal` subtrees** (`gpui-go/internal/abi`, `…/nativeloader`, `…/scenebridge`, `…/textbridge`, `…/a11ybridge`, `…/win32host`, `…/nativeassets`). An `internal` directory directly beneath a package restricts imports to **that subtree, not the whole module**; placing `internal` at the module root extends the restriction module-wide ([internal rule](https://go.dev/cmd/go#hdr-Internal_directories), [modules reference](https://go.dev/ref/mod)) — which is what a private ABI needs. `authoring` is already an independent package; the canonical plan is **shared definitions below the root with compatible aliases where needed**, with the only hard rule being no root/authoring import cycle (both directions), subject to the authoring-signature gate. The root package re-exports no internal types; all internal dependencies point inward toward `abi`/`nativeloader`. Generated code remains a later decision.

## 2. One combined native service DLL

Main's selection: **a single maintainer-built service DLL** containing all four services as **distinct logical service tables** — layout (Taffy), text (parley stack + rasterizer), renderer/scene/atlas/capture, AccessKit/COM adapters, and (per §11) image/SVG decode — with exact release + hash coupling to the Go module, static CRT, and process-lifetime load. Rationale: a single artifact avoids cross-DLL COM, allocator, and ABI-version combination matrices entirely; licensing does not require independent binaries (notices are a packaging matter); a shared process address space means separate DLLs were never crash isolation; and cross-service changes require full integration gates regardless. The separate-DLL alternative (independent per-service versioning and re-validation) remains recorded, but the loader abstracts grouping, so nothing in the Go API depends on the choice. No size or performance prediction is made — unmeasured.

One placement rule inherited from the renderer review: the capture producer obtains `IDXGIDevice` by `QueryInterface` on the actual `ID3D11Device` — **the QI is expected to succeed but its HRESULT is checked and reported; no "always succeeds" claim** — and never uses the renderer's DComp-gated `dxgi_device` member.

**Architecture baseline and feature matrix.** Windows AMD64 on the recorded current PC. Wrong-architecture or otherwise unloadable artifacts surface as typed load errors. Optional capabilities are explicit compiled features: **screen capture is compiled in for the chosen baseline** (it is part of the full-core target); its OS runtime availability may legitimately be unavailable at run time (denied, driver-dependent) — a missing *compiled* capability is an initialization error, never silent degradation. The pin's wgpu/custom-GPU surface is not compiled and not implied.

## 3. Artifact delivery: embed in the module

`//go:embed` under `gpui-go/internal/nativeassets`, extracted once to a per-user directory ([embed](https://pkg.go.dev/embed)). Constraints from the module system: the **module zip has a 500 MiB ceiling** ([zip files](https://go.dev/ref/mod#zip-files)), so the combined DLL plus provenance must fit — unmeasured, and a gate; **no git-LFS pointer files** may masquerade as binaries (an LFS pointer embeds as text — binaries must be committed as real bytes); the manifest records **exact asset paths and SHA-256 hashes**, and there is **no automatic upgrade** — a new module version is the only upgrade path. Bundle-adjacent files (release bundle) load via an explicit directory override, verified identically. First-run network fetch is rejected as a default (TOFU trust and a runtime network dependency).

**Publication and concurrency protocol** (corrected: `os.Rename` gives no atomicity guarantee on Windows — ["Even within the same directory, on non-Unix platforms rename is not an atomic operation"](https://pkg.go.dev/os#Rename)): (1) the destination filename is the **full content hash**, so different content never targets one path; (2) publication writes a unique temp name in the same directory, then renames into the hash-named final path; (3) a per-user lock file serializes publisher transitions; (4) after publication, the loader opens the file with **read-only share mode (no write/delete sharing) and verifies the hash again at open** — an open handle that cannot be opened with write/delete share is the actual exclusion proof, not the rename; (5) a pre-existing verified hash-named file is success for concurrent processes. **No untrusted temp-directory fallback**: if the per-user cache directory is unwritable, the required-service error explicitly tells the consumer to use the bundle-override mode; read-only environments use the explicit bundle. Offline: module cache + extracted cache + bundle all work without network.

## 4. Secure loading, FFI, and the panic boundary

**Explicit loading path** (corrected: `NewLazyDLL`'s default loading does not enforce the selected flags): call the Go wrapper `windows.LoadLibraryEx` (which invokes the OS symbol **`LoadLibraryExW`**) with `LOAD_LIBRARY_SEARCH_SYSTEM32` and resolve exports via `GetProcAddress` — never the lazy default ([LoadLibraryExW](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-loadlibraryexw), [search order](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order)). `LOAD_LIBRARY_SEARCH_SYSTEM32` (rather than also `LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR`) is selected because the single artifact has **no private companion DLL imports**; if future artifacts need companions, the canonical alternative is a verified artifact directory plus `LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR` — never global search paths. **Isolation is best-effort, not absolute** (corrected): the loaded-module caveat applies to *dependency resolution by name and already-loaded modules* — Windows still applies its loaded-module/API-set rules, so these flags are not universal in-process dependency isolation, and no claim is made that a top-level absolute-path load always bypasses same-basename reuse. The DLL's distinctive hash-suffixed name makes collisions with an application's own libraries vanishingly unlikely. `SetDefaultDllDirectories` is not used (no process-wide change).

FFI mechanics: `golang.org/x/sys/windows` under `CGO_ENABLED=0` (the std precedent; no package imports `"C""). Per the installed Go syscall implementation, amd64 `Proc.Call` **does support float arguments and returns** ([dll_windows.go](https://cs.opensource.google/go/go/+/go1.27.1:src/syscall/dll_windows.go)) — the private ABI's integer/pointer/struct-field-only convention is therefore a **deliberate simplifying restriction** (predictable marshaling, no per-platform float-register plumbing), not a platform impossibility. `NewCallback` constraints stand (stdcall, one uintptr result, arguments no larger than `uintptr`, ≥1024 budget, never-released memory → fixed trampolines with generation tokens) ([syscall_windows.go](https://github.com/golang/go/blob/go1.27.1/src/syscall/syscall_windows.go)). Panic boundary: Go trampolines recover; Rust exports are unwind-enabled and `catch_unwind`-wrapped; no panic crosses.

## 5. Version coupling, ABI negotiation, error behavior

The DLL exports per-service identity records: ABI major/minor, build hash, CE pin `254b5dbd47cbb5acbcc5bbdcbb322a339276c88a`, provenance (lock hash, feature record, toolchain). The Go loader enforces: major exact, minor ≥ expected, SHA-256 match against the embedded manifest; mismatches are typed load-time errors (not-found, extraction-failure, hash-mismatch, abi-mismatch, arch-mismatch, missing-required-feature) naming versions, hashes, and attempted locations. Required services fail fast at initialization; runtime-unavailable *OS* capabilities (e.g., capture denied) report capability errors without killing the app. Because the DLL is embedded in the module, coupling is exact per release; negotiation exists for the bundle-override path and additive evolution.

## 6. Provenance, hashes, licenses

Per-artifact manifest (embedded and hashed): Rust toolchain identity, `Cargo.lock` hash, resolved target feature graph, naga/naga-old/wgsl-rs versions and revs, WGSL/DXBC hashes, compiler flags, target triple, and **import inspection evidence** (the build must inspect the DLL's imports and record that no dynamic-CRT runtime DLL is imported — §7). License inventory from verified primary sources — notice obligations only, no module-license inference: GPUI-CE **Apache-2.0**; Taffy 0.13.0 **MIT**; parley stack 0.11.1 **Apache-2.0 OR MIT**; accesskit 0.24.1 **MIT OR Apache-2.0**; remaining entries (etagere, skrifa, swash, harfrust, `image`, resvg/usvg, `windows` crates) recorded at build time; the pin's [THIRD_PARTY_NOTICES.md](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui_render/THIRD_PARTY_NOTICES.md) is the upstream aggregation point. The distribution carries the complete notice set.

## 7. Rust MSVC runtime: static CRT

Build with **`-C target-feature=+crt-static`** — the documented mechanism for statically linking the MSVC C runtime ([rustc targets: static C runtime](https://doc.rust-lang.org/rustc/targets/index.html#static-c-runtime)). MSVC-target Rust defaults to the dynamic CRT, which depends on the Visual C++ redistributable not being guaranteed on clean machines ([redistributing Visual C++ files](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files?view=msvc-170)). Static CRT in one combined DLL avoids both the redist dependency and cross-DLL allocator hazards; unwind (`panic = "unwind"`, `catch_unwind` in exports) is compatible — the actual unwind hazard is foreign-frame unwinding, which the panic boundary forbids. The build must override Taffy's workspace `panic = 'abort'` release profile and **verify the final imports list** as recorded evidence.

## 8. PerMonitorV2 awareness from pure Go

Unchanged: the pin embeds its manifest; a library cannot force a resource into a consumer exe ([manifests](https://learn.microsoft.com/en-us/windows/win32/sbscs/application-manifests), [DPI setting](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process)). Proposal: a pure-Go `.syso` resource generator (RT_MANIFEST; the Go linker consumes COFF objects — no compiler beyond Go), plus a guarded `SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)` fallback before any HWND/COM initialization when the manifest is absent ([API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setprocessdpiawarenesscontext)); no mixing. Consumer-side opt-in, documented by the module.

## 9. Process lifetime and unload

Unchanged from review: load for process lifetime, **never `FreeLibrary`** once provider/query/capture capabilities activate ([FreeLibrary rules](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-freelibrary)); the lease ledger still governs shutdown ordering and reports outstanding obligations. **No debug hot-unload path is selected** in the initial design — module residency is unconditional once loaded; logical services, buffers, engines, windows, COM objects and GPU resources still close per their contracts.

## 10. Consumer contract and unexecuted gates

`CGO_ENABLED=0 go build` of an app importing `gpui-go` (+ optional `authoring`), embedded artifact extracted on first run, no Rust/C/shader toolchain, no network, no process-wide loader changes, PerMonitorV2 via `.syso` or guarded API. Gates: clean-machine build+run; typed-error injection for every failure class; concurrent first-run publication; unwritable-cache → bundle-override path; bundle loading with verification; ABI mismatch; callbacks under GC pressure; panic containment both directions; COM references outlasting windows; full retirement/shutdown ordering; module-zip size compliance (500 MiB). No benchmark or size claim.

## 11. Asset and SVG seam audit (primary sources)

The pin's asset/image/SVG capability set — part of the full-core target, not optional — was traced to decide where it lives in the combined DLL:

- **Asset system** ([assets.rs](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/assets.rs)): `AssetRegistry` (BTreeMap of path → `PreLoaded` bytes or `OnDemand` thread-safe loader closure; `rust_embed` integration behind the `embedded-assets` feature; duplicate-path errors). **Go owns this**: registry, source resolution, on-demand loading tasks, cache keys — no arbitrary worker callbacks into Go from native.
- **Image decode** ([platform.rs](../evidence/core/crates__gpui__src__platform.rs), [img.rs](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/elements/img.rs)): `decode_static_image` uses `ImageReader::into_decoder` → **EXIF orientation read and applied** → RGBA→**BGRA** swap → single frame; `ImageFormat` covers Png/Jpeg/Webp/Gif/Svg/Bmp/Tiff/Ico/Pnm; the `img()` element's extension list adds avif/tga/dds/hdr/exr/qoi/farbfeld via the `image` crate; sources are `Resource` (URI → `cx.http_client()`, Path → `fs::read`, Embedded → registry), `RenderImage`, `Image`, or a custom loader; a 200 ms loading-delay state, animation advance gated on window-active/reduce-motion, per-element or global `ImageCache`, and a concrete error taxonomy (bad HTTP status with body, asset-missing, image/SVG errors). **The two WebP paths differ and must not be silently combined**: the `img()` resource loader checks `has_animation()` and decodes animated WebP frame-by-frame with per-frame delays (RGBA→BGRA per frame) while falling back to static decode; the platform `Image::to_image_data` path (clipboard and `Arc<Image>` assets) decodes WebP **statically only**. The decode ABI therefore carries an explicit mode (static vs animation-capable) selected by the caller, matching each pinned entry point.
- **SVG** ([svg_renderer.rs](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/svg_renderer.rs)): `usvg` parse (text→paths at parse, so a `ParsedSvg` is reusable across raster scales) + `resvg`/`tiny-skia` rasterization; smooth-scale factor 2; **8192 px cap**; output conversion via `swap_rgba_pa_to_bgra` — **not a mere channel swap: it swaps R/B and unpremultiplies** (each channel divided by normalized alpha, with the pinned truncating `as u8` cast) — i.e. tiny-skia's **premultiplied RGBA becomes straight-alpha BGRA** ([color.rs](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/color.rs)); **alpha-mask rendering for path icons**; a custom font resolver over the system font DB plus **bundled fonts loaded from the asset registry** (`fonts/ibm-plex-sans/IBMPlexSans-Regular.ttf`, `fonts/lilex/Lilex-Regular.ttf`), generic-family fixes, and an emoji fallback (Windows: "Segoe UI Emoji", "Segoe UI Symbol") checked via skrifa charmaps.
- **Locked versions**: `image` manifest range 0.25.1 resolves to **0.25.10** in the pin's lock ([Cargo.lock](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/Cargo.lock)); `resvg` 0.48.1 (`text`, `system-fonts`, `memmap-fonts`, `raster-images`), `usvg` 0.48.1 (root manifest).

**Fit and ownership decision**: the pinned image + resvg/usvg stack joins the **combined DLL** as additional service tables — `decode_image(bytes, format_tag, entry_mode) → frames`, SVG parse/render and alpha-mask operations. This retains source algorithms behind finite records; it does not prove parity or a cost advantage. Preserve the pinned unpremultiply arithmetic. `entry_mode` distinguishes clipboard/explicit-Image conversion from resource loading: WebP is static in the former and animation-aware in the latter; **GIF can animate in both**. It is not a global static-versus-animated switch.

**Go owns sources, cache, and tasks**: resource resolution, registry, background loading scopes and cache keys. **Bundled fonts stay lazy**. Use a `NeedsFontAssets` status with an owned suspended request, not a native worker callback into Go: return to the Go task orchestration, resolve/copy the requested two-path font inputs, and resume native work. Do not force all CPU decoding onto the foreground thread. Preserve the captured renderer's lazy enriched-font database lifetime, absent-font results and cancellation cleanup. This request/resume mechanism is a Go bridge adaptation needing source-trace tests, not existing pinned behavior. The [canonical distribution contract](../docs/distribution-contract.md) owns the final selection.

**HTTP client seam — closed.** The pinned contract is small and fully injectable ([http_client.rs](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/http_client.rs)): a trait `HttpClient: 'static + Send + Sync` with a single operation `get(url, follow_redirects: bool) → boxed future of Result<HttpResponse>`, where `HttpResponse` is exactly `{status: http::StatusCode, body: Vec<u8>}` — GET-only, full-response, no streaming, no headers exposed. Implementations in the pin: **`NullHttpClient` (always errors "No HttpClient available"), used as the `App::new` default** ([app.rs](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app.rs) constructs it); `BlockedHttpClient` (permission-denied error); `FakeHttpClient` (test-support only, canned 200/404); injection via `with_http_client`/`set_http_client`. The image loader calls `client.get(uri, true)` — **follow-redirects = true** — and maps non-success statuses into `ImageCacheError::BadStatus` with the body's first line. **Answer: yes — preserving an injected Go interface with a Null default is sufficient parity.** The Go port defines `HttpClient` as a public interface (`Get(url string, followRedirects bool) (HttpResponse, error)` over the same two-field response), defaults the app to a null client with the same "no client available" error, and routes URI image loads through it with follow-redirects true. Any adapter over Go's standard `net/http` is **explicit caller configuration only** — the framework never installs it as a default, so no application silently gains network behavior the pin's default denies. Remaining behavioral details (redirect limits, timeouts, TLS policy) belong to whichever adapter the application configures and are conformance fixtures for adapter authors, not framework seams; the pin itself specifies none beyond the boolean. No other asset/SVG gap requires a new planning decision: animated-frame delays, EXIF, alpha-mask icons, the 8192 cap, and the system-font DB are finite record semantics or the same OS the DLL runs on.
