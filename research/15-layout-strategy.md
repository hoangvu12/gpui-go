## 1. Pinned dependency and engine facts (verified)

**Resolution.** The gpui crate manifest requests `taffy = "=0.13.0"` with no feature selection ([gpui Cargo.toml](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/Cargo.toml)). The pinned lockfile resolves exactly one taffy entry: version 0.13.0, source `registry+https://github.com/rust-lang/crates.io-index`, checksum `c034e05f6ee85a12daa63863c2245797715075c70649947aa0da54f3f2ab1d0f`, dependencies `arrayvec, serde, slotmap, smallvec` ([Cargo.lock](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/Cargo.lock)). The workspace root manifest has no `[patch]` section and no Taffy entry, and the lock shows registry resolution — those two facts bound this absence claim; nothing was searched beyond the root manifest and lockfile.

**Features.** Taffy 0.13.0's own manifest defines its default set as `std, taffy_tree, flexbox, grid, block_layout, float_layout, calc, content_size, detailed_layout_info` ([taffy Cargo.toml](https://github.com/DioxusLabs/taffy/blob/v0.13.0/Cargo.toml)); since the gpui manifest selects no features, those defaults apply. The lock's dependency list is a union across workspace targets and feature combinations, **not** an activation report: the bridge/oracle build must record the actual resolved target feature graph at build time, which is a build-record obligation, not something the lock can prove.

**Engine split and used surface.** `TaffyLayoutEngine` wraps `TaffyTree<NodeContext>` with `disable_rounding()`, and GPUI's own bookkeeping (absolute-bounds caches, unrounded f32 origins, vertical alignments, inline content/fragment maps, display/position maps) lives outside Taffy ([taffy.rs](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/taffy.rs)). The used Taffy surface: `new_leaf`, `new_with_children`, `new_leaf_with_context`, `set_style`, `style`, `layout`, `parent`, `children`, `compute_layout_with_measure`, `clear`. Style translation combines the `ToTaffy` trait with the `From<Display>` conversions in [style.rs](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/style.rs), where `Inline → Block`, `InlineFlex → Flex`, `Grid → Grid`, `None → None` (verified above) — confirming the main contract's mapping. GPUI forwards: display/overflow/scrollbar width, position/inset, size/min/max/aspect, margin/padding/border, alignment, gap, flex fields, grid repeat templates (`minmax(0,1fr)`, `minmax(min-content,1fr)`, `minmax(0,max-content)`) and placement lines; all other Taffy fields keep their pinned defaults; those defaults can affect parity without becoming additional public GPUI properties.

**Rounding helpers (source-verified, not a gap).** The pinned [util.rs](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/util.rs) defines exactly: `round_half_toward_zero(v) = (v.abs() − 0.5).ceil().copysign(v)`; `round_to_device_pixel(l, s) = round_half_toward_zero(l * s)`; `round_stroke_to_device_pixel(l, s) = 0.0` if `l == 0.0` else `round_to_device_pixel(l.max(0.0), s).max(1.0)`; `ceil_to_device_pixel(l, s) = (l * s).ceil()`. Pinned tests anchor 0.5→0, 1.5→1, −1.5→−1, stroke 0.4→1.0/0.5→1.0/1.6→2.0. Measured leaf sizes clamp each logical dimension nonnegative, then scale and ceil. Padding on an auto-sized axis snaps the pair total and redistributes in the authored ratio (nonnegative edges, positive total; other cases use ordinary conversion). Post-layout: unrounded absolute device origins accumulate, near and far outer edges round independently with midpoints toward zero, sizes subtract, then divide by scale; the text parent-relative path is the exception, with inline-fragment and parentless nodes falling back to absolute snapping. `computed_layouts` tracks computed roots so that **recomputing an already-computed root invalidates its subtree's cached bounds** — it does not skip or deduplicate compute work.

**Measurement, phases, inline.** Measured leaves register `FnMut(Size<Option<Pixels>>, Size<AvailableSpace>, &mut Window, &mut App) -> Size<Pixels>`; Taffy computes in device pixels (definite available space scaled up, known dimensions scaled down into the callback, measured result snapped). Window entrypoints assert the request-layout/prepaint phase ([window.rs](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/window.rs#L5237-L5330)); `compute_layout` takes the engine out of the window during compute, so same-engine recursion hits the `None` unwrap and panics. `clear()` resets the tree and maps each frame; `place_inline` inserts a detached inline box and invalidates descendants. Inline text/atomic-box orchestration is GPUI-owned, never a Taffy tree.

## 2. Engine selection: version-pinned native Taffy bridge

The investigated pure-Go candidates are **not verified equivalent** to the pin — Gio's Flex is a weighted-axis layout; the inspected SCKelemen/layout candidate documents unrepresentable `flex-shrink: 0`, missing percentages, simplified intrinsic sizing, and rune-count text measurement ([limitations](https://github.com/SCKelemen/layout/blob/6f7349411616cbb31fc83c4b5d8baf48ccccebcb/docs/limitations.md)) — and no broader survey claims nothing else could exist. A faithful pure-Go port remains a possible later replacement behind the same test surface, per the main contract.

**Selection: a maintainer-built Windows DLL wrapping the locked Taffy build behind an explicit versioned C ABI, loaded from Go with `golang.org/x/sys/windows`** (chosen over the standard `syscall` package for its maintained Windows surface). Consumer builds stay pure Go with `CGO_ENABLED=0`; cgo is rejected because packages importing `"C"` fail to build without a C compiler ([cgo docs](https://pkg.go.dev/cmd/cgo)). Maintainers need the Rust toolchain, consistent with the accepted native-dependency policy; the DLL is a **product to build and verify, not an existing one**. This selection concentrates new compatibility work in the ABI and Go-side GPUI adapter — it is not a claim that algorithmic parity follows from construction; only the differential corpus can establish the bridge's parity.

## 3. Bridge ABI contract

**Record rules.** Fixed-width fields, explicit tags and presence flags, capacity/written-count pairs, version/size headers on every record, validated opaque handles — engine handles and node handles are distinct id spaces. Floats cross as `f32` bit patterns or as fields of pointer-addressed fixed-layout records, never as positional word arguments; booleans as `u32` 0/1; no Rust `enum`/`Vec`/slice/string/closure crosses by native representation. **Callbacks carry a word-sized cookie plus a pointer to a native-owned fixed request record** containing independent presence flags for known width and height, **independent available-space tags per axis** (mixed Definite/MinContent modes are representable), each definite value's `f32` bits, and the engine/node identities and compute tokens; the Go trampoline reads the record, dispatches through a generation-checked registry (tokens are generation-stamped, never recycled as raw numbers), and writes a response record copied by native before return. No Go object or closure pointer is retained natively.

| Call family | Notes |
|---|---|
| engine create / reset / dispose | engine handles; disposal only after active calls return |
| node create (children list / measured) | **returns a new validated node id**; measured form registers a cookie |
| set style, root stretch | root auto-fill in device units |
| compute (root, request record) | same-engine reentrancy rejected **before** native entry |
| query geometry (incl. parent), children traversal | copied results into Go-owned storage |
| clear / stale-id policy | post-clear ids fail with explicit status |

**Reentrancy and threading.** Recursion is rejected only for the **same engine** — nested use of *independent* engines (separate windows/build scopes) is legitimate and uses per-engine busy guards and local call state, never a global mutex held across application callbacks. All calls run on the foreground thread under `runtime.LockOSThread`; the measure callback is synchronous, same-thread, may do text measurement and entity access, and must not block. The loaded library stays alive while any engine, call, or callback can reference it; registry entries are removed only after the associated native call finishes — no scope close frees memory a running callback still uses.

**Ownership of buffers.** `Proc.Call` does not magically own arbitrary Go slice pointers, especially across callbacks where the GC may run: any borrowed Go buffer used for a synchronous transfer must be pointer-free and explicitly pinned/kept alive for the call, or the buffer is native-owned with results copied into Go storage before native release. `uintptr` alone is not ownership. The bridge's explicit `u32` status return is authoritative; the procedure-call last-error value does not establish failure.

**Panic containment.** The bridge's build profile must enable unwinding — Taffy's own workspace sets `panic = 'abort'` in release, and a bridge that inherits an aborting profile cannot `catch_unwind` — so every exported call is wrapped and the profile is a recorded build requirement. Go-side: the trampoline recovers a panicking measure func, **latches failure**, suppresses further user callbacks during that compute, and discards the result; since Taffy's measure signature returns a size rather than `Result`, any sentinel size the native side must produce is internal failure plumbing, never a successful layout. The failed engine is marked for reset/disposal, and the original Go panic is re-raised only after the native call has returned and Go-side bookkeeping is restored. Unwinding never crosses the ABI; aborting faults are not promised recoverable.

## 4. What stays Go-side

Per the pin's own split: Taffy tree/compute/style crosses the bridge; the absolute-bounds caches, unrounded origins, vertical alignment, display/position maps, inline content/fragment bookkeeping, `place_inline` invalidation, root auto-stretch driver, and the full two-phase snapping arithmetic (helpers quoted in §1) are Go-side deterministic arithmetic over returned f32 layouts, differentially testable in isolation. Layout IDs carry engine identity and generation; they are not persistent element-state keys.

## 5. Differential verification

**Oracle.** An **independent Rust harness around the pinned gpui `TaffyLayoutEngine`** — not the bridge comparing itself — drives the locked Taffy with deterministic fake-metric measurement functions and records every node's raw and snapped bounds plus the full callback request/result transcript. The Go bridge runs the same semantic style trees, rem/scale, and available space.

**Matching discipline.** Callback transcripts are keyed on actual inputs: the harness asserts each callback's known-dimension flags, available-space tags, and definite bits match the recorded request before feeding the recorded response — a changed callback query is a mismatch to investigate, not a cue to replay responses by ordinal. Gates require exact per-node tags, tree relationships, callback input order under identical cache history, and bit-for-bit `f32` bounds (signed zero normalized only where a fixture says so).

**Fixture matrix.** Auto/explicit roots; percentages with indefinite parents; zero/min/max-content space; min/max/aspect constraints; flex shrink-zero/grow/wrap/baseline; absolute positioning/overflow; grid repeat/span/placement; rem overrides; fractional DPI; negative and half-pixel coordinates; borders and proportional padding; repeated measurement/recompute; text parent-relative snapping; inline atomic boxes/fragments and detached placement; reset/stale ids; cached-frame reuse; aborted/nested construction.

**Gating and sequencing.** Deterministic fake metrics isolate layout from fonts (the Windows-font suite is ticket 06's). The ABI-level checks (record size/alignment, f32 round trips, forced GC during callbacks, same-engine reentry rejection, callback panic, failed compute, clean `CGO_ENABLED=0` consumer build with the prebuilt DLL) require no Go 1.27 language features, hence are independent of ticket 10's signature work — but that independence **does not authorize probing with the currently installed older toolchain**: all execution waits for the authorized toolchain, with tickets 08 (artifact provenance/signing/loading) and 09 (CI gates) recording the runs.

## 6. Honest limits

No substantive unsafe or unresolved gap was identified in the main contract during this review.
