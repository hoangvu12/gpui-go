## 1. Upstream facts (*source*)

**Retention and release.** Handles are logically reference-counted: `AnyEntity::clone` increments the count, `Drop` decrements, and the last decrement queues the entity id; `AnyWeakEntity::upgrade` succeeds only while the count is nonzero ([clone/drop](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app/entity_map.rs#L311-L352), [take_dropped](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app/entity_map.rs#L184-L205)). Release is an effect-loop stage: `release_dropped_entities` drains the dropped queue and, per entity, removes observers, event listeners, window invalidators, and the current-window entry, then runs release callbacks with the state still available ([release path](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app.rs#L1834-L1852)); focused-handle release runs in the same stage ([focus release](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app.rs#L1854-L1870)). Update is a lease: the value leaves the map during the callback; reentrant access panics ([lease](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app/entity_map.rs#L134-L160)).

**Effect loop.** Effects live in a FIFO `VecDeque`; nested updates count `pending_updates` and only the outermost, non-flushing update flushes; effects can enqueue more effects and flushing drains fully ([nesting](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app.rs#L1138-L1157), [flush](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app.rs#L1764-L1830)). Each iteration first releases dropped entities and focus handles, then pops one effect. `notify` coalesces via a pending set; `apply_notify_effect` removes the id *before* observers run, so re-notify re-enqueues ([notify effect](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app.rs#L1876-L1882)). `emit` queues one effect per occurrence, keyed by entity id and declared payload type; the event arena is cleared only after the queue drains ([emit](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app.rs#L2963-L2975)) — so payload-reference drops from that clear can themselves trigger releases that land in a *later* cycle. Subscription registration is inert until a deferred activation effect runs ([deferred activation](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app.rs#L1263-L1270)); a subscription canceled by an earlier callback does not fire, and registrations added during delivery wait for the next emission ([subscriber set](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/subscription.rs#L62-L148)).

**Subscriptions, capture, and tasks.** Dropping a `Subscription` cancels; `detach` keeps the registration until its participating entities are gone; `join` merges cancellation ([subscription](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/subscription.rs#L150-L180)). `Context::listener` captures the target weakly; `processor` and `on_next_frame` capture strongly ([listener](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app/context.rs#L252-L272), [on_next_frame](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app/context.rs#L292-L301)); `Context::spawn` hands the future a weak entity ([spawn](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app/context.rs#L237-L248)). Foreground tasks run FIFO on the main thread — priority is ignored — with idle spawning; background tasks are `Send` futures on a pool ([foreground FIFO](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/executor.rs#L355-L390), [background](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/executor.rs#L106-L130)); scheduler tasks detach to run to completion, otherwise cancel when dropped ([task detach](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui_scheduler/src/executor.rs#L549-L560)). Window-scoped delivery no-ops when the subscriber's window is unavailable ([window-scoped subscribe](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app/context.rs#L355-L395)).

**Frame and test mechanics.** Keyed element state is a per-frame map keyed by `(GlobalElementId, TypeId)`; at frame finish, states *accessed* during the new frame move from the old frame, unaccessed state drops with it ([frame state](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/window.rs#L1103-L1104), [finish](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/window.rs#L1225-L1234)). Cached views are reused unless the entity is dirty, the window refreshes, or the cache key (bounds/content mask/text style) changed; a `ViewElement` consumes its view at first expansion, and cache reuse replays the recorded prepaint/paint ranges and extends accessed-entity dependencies ([view caching](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/view.rs#L354-L398)). The test platform is explicitly deterministic: manual clock, tick loops, `run_until_parked`, parking control, CPU-count override ([test dispatcher](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/platform/test/dispatcher.rs#L56-L95), [test context](https://github.com/gpui-ce/gpui-ce/blob/254b5dbd47cbb5acbcc5bbdcbb322a339276c88a/crates/gpui/src/app/test_context.rs#L494-L515)).

## 2. Go lifetime model (*adaptation, selected*)

Go facts forcing adaptation, with official references: [runtime.AddCleanup](https://pkg.go.dev/runtime#AddCleanup) is asynchronous, unordered, and not guaranteed to run; [weak.Pointer](https://pkg.go.dev/weak#Pointer) follows GC reachability, not logical lifetime; plain assignment cannot change a strong count; map iteration order is unspecified and unstable ([spec](https://go.dev/ref/spec#For_statements)). None implements the pinned observables, so: **explicit logical leases grouped in named scopes**, plus deterministic release processing on the foreground loop.

```go
// Documentation syntax; uncompiled.
type Entity[S] struct{ lease *entityLease } // borrowed OR owned; copies alias one lease

func NewEntity[S any](cx AppContext, scope *Scope, build func(*S, *Context[S])) Entity[S]

// Independent ownership always lands in a live named scope:
func (h Entity[S]) RetainInto(scope *Scope) Entity[S]       // +1, scope-owned
func (h WeakEntity[S]) UpgradeInto(scope *Scope) (Entity[S], bool) // +1 on success
func (h Entity[S]) Downgrade() WeakEntity[S]
func (s *Scope) Transfer(dst *Scope, h Entity[S]) // atomically moves ONE lease; closed dst rejected
func (h *Entity[S]) Release() // valid only on a scope-owned lease; idempotent per lease
```

- **Borrowed vs owned.** Handles obtained from `cx.Entity()`, callback sources, and render arguments are *borrowed, callback-limited*: valid because the framework pins the entity for the callback's duration (an internal temporary count released when the callback returns — no hidden per-render lease leak). Persisting one requires `RetainInto(scope)`; `Release` on a borrowed handle is misuse and panics with a diagnostic. Owned leases mint only into a live named scope — there is no ownerless `Retain` or `Detach` for entities. `Transfer` moves exactly one lease atomically between scopes, rejecting a closed destination; plain copies alias and cannot double-release (one decrement, idempotent per-lease flag).
- **Scope close.** Idempotent; deterministic order: scope-owned leases, subscriptions, and tasks release in registration order, on the foreground, inside the effect loop. A scope releases only what it owns; an entity's final release can still wait on external counts held by other scopes or windows — closing one window never kills another window's retains.
- **Generations.** `EntityId` is slot + generation. Release bumps the generation; weak upgrade checks it, so released entities cannot be resurrected and stale handles fail at the access boundary (misuse panic, like the pinned over-release asserts).
- **Cycles.** An A→B→A strong cycle never reaches zero, so `OnRelease` never runs — release hooks only tear down *acyclic* outgoing dependencies after zero. Cycle management is therefore earlier and explicit (*adaptation*): weak backedges by convention for reverse/parent references, or an explicit early `Dispose`/break-edge API that deterministically drops one strong edge before zero. The default weak edges for callbacks and observers match the pin's weak listener capture. Debug builds get leak detection reporting unbroken cycles (parity with the pin's leak-detection feature). Scopes do not pretend to collect entity-owned cycles.
- **Native cleanup.** `OnRelease` callbacks run with state available, mirroring the pinned order (registrations removed first). Native owners queue an explicit release step for the foreground; retirement waits on backend completion fences, not a guessed frame counter. Backend mechanism is another ticket.

## 3. Subscriptions, tasks, cross-window behavior (*adaptation, selected*)

```go
type Subscription struct{ /* owner kind: window-scope or entity-scope */ }
func (s Subscription) Cancel()       // idempotent
func (s Subscription) Detach()       // weak endpoints; lives until emitter/subscriber released
func (s Subscription) Transfer(scope *Scope) // moves cancellation ownership only
func Join(a, b Subscription) Subscription

type Task[R any] struct{ ... }
func (t Task[R]) Detach() // transfers to the app-owned detached-task registry
func (t Task[R]) Cancel() // cooperative: may never be observed by a busy worker
```

- **Subscription ownership is explicit and scoped.** Go has no drop-hook: a discarded `Subscription` cancels nothing. Every subscription names its owner: a *window scope* (created during window setup — closing that window cancels it) or a *subscriber entity scope* (created during entity setup — released with that entity). Closing window A cancels only A-owned registrations; an entity-scope subscription used by both windows A and B survives A's closure. `Detach` leaves the weak endpoints unchanged (it lives until emitter or subscriber is released, upstream parity); `Transfer` moves cancellation ownership without changing endpoint lifetimes. Delivery rules follow the pin: insertion-ordered iteration, canceled-in-pass subscriptions skipped, new registrations deferred, activation deferred.
- **Strong-capture parity is explicit.** Listener adapters stay weak. `OnNextFrame` and the strong processor equivalent are *owned* registrations: the frame registration list (window-owned) or the creating scope retains the entity for the callback's lifetime and releases it after — strong capture by explicit owner, never an accidental default.
- **Tasks.** Foreground execution is FIFO on the UI thread (priority ignored, source parity) with an idle variant; background work runs on a goroutine pool. `Cancel` is cooperative ([context.CancelFunc](https://pkg.go.dev/context#CancelFunc)-style signaling) and may never be observed by a worker that never checks — stated plainly; the framework never kills goroutines. `Detach` transfers the task to an **app-owned detached-task registry**, the explicit owner until completion or app shutdown — not "owns itself." Worker-retained dependencies hold until the *worker actually exits*, not until the result is posted. All state changes happen on the foreground ([LockOSThread](https://pkg.go.dev/runtime#LockOSThread) provides affinity; the loop provides ownership). Workers receive only a `WeakEntity` and a posting function — no `*Context[T]`, `*Window`, or `*S` pointers escape. The late-result gate checks the task's scope token and the entity generation *even if the entity is independently retained elsewhere*: a retained-but-out-of-scope result is dropped, not applied.

## 4. Effects and scheduling state machine

| State | Rule (*source* unless noted) |
|---|---|
| `pendingUpdates` | nesting counter; flush only at outermost exit when not already flushing |
| effects queue | strict FIFO; callbacks enqueue; loop drains fully |
| per iteration | release dropped entities → release dropped focus handles → pop one effect |
| notify | coalesce while pending; remove from pending set before observers; re-notify re-enqueues |
| emit | one effect per occurrence, call order; key = entity id + declared payload type |
| payload arena | cleared after the queue drains — payload retirement can queue releases for a *later* cycle |

Delivery order is registration order (upstream's id-ordered map). Go map iteration is randomized by default, so the port commits to insertion-ordered subscriber lists — a design commitment, not a language gift. Determinism of the *whole* test run needs more than one foreground loop: seeded worker scheduling, virtual time, controlled worker-completion ordering, and recorded/replayed external inputs — an *adaptation* extending the pinned deterministic dispatcher.

**Event payload ownership (*adaptation, selected*).** Plain `Emit(cx, p)` snapshots the value; the framework neither auto-retains nor auto-releases entity/native handles reachable from `P` — such handles in an arbitrary payload are not discovered or released by the event system. For payloads containing mutable reachable data (slices, maps, pointers), the convention is **freeze-until-retirement**: the emitter must not mutate data reachable from the payload until the emission's payload scope retires at end-of-cycle arena clearing, and subscribers treat the delivered payload as read-only. No blanket "never retain the value" claim is made for immutable plain values like ints. When a payload should own dependencies, use the explicit owned form:

```go
func (e Event[S, P]) EmitOwned(cx *Context[S], build func(payloadScope *Scope) P)
```

The builder may `RetainInto(payloadScope)`; when the payload scope retires after delivery, those deps release. Preserving the pin's end-of-cycle arena retirement means payload-scope retirement can queue releases *after* the last release pass of a cycle; the framework schedules a subsequent foreground flush to process them — a labeled liveness adaptation, not a same-cycle fixed-point promise.

## 5. Stress checks

1. **Retain across windows:** B's `RetainInto(windowB)` is an independent count; closing A releases only A's scope; the entity survives; aliased copies of one lease release once.
2. **A→B→A strong cycle:** never reaches zero; break earlier via weak backedge or explicit `Dispose` of one edge; `OnRelease` would only have torn down acyclic deps after zero; leak detection reports it in debug.
3. **Self-subscribe, source released while queued:** the release stage at loop top removes the emitter's listeners before the queued `Emit` pops — no-op; the weak path also fails closed.
4. **Notify×2, Emit 1,2, nested defer:** one coalesced notify effect, two emit effects in order, defer appended; FIFO processing; observers see the final count; subscribers receive 1 then 2; re-notify during delivery enqueues a new pass.
5. **Callback cancels next callback:** insertion-ordered delivery checks the dropped flag per subscriber; canceled subscription skipped in-pass; new registrations deferred.
6. **Worker races owner closure:** worker posts to the foreground; the gate checks task scope token + entity generation (independent retains do not rescue an out-of-scope result) → dropped; worker-retained deps release at actual worker exit; detached tasks live in the app registry until completion.
7. **Cached view remove/reinsert, key reuse, abort with GPU in flight:** keyed state is owned by the window, keyed by `(GlobalElementId, type)` plus the framework's frame machinery, and survives only while accessed each frame — removal and reinsertion under the *same* key yield fresh state, independent of entity-slot generation. A cache hit replays the recorded prepaint/paint ranges and carries the recorded accessed-entity dependencies. Frame abort keeps the last *published* frame artifacts on screen, disposes the uncommitted frame scope, and does not roll back arbitrary application mutations performed by prepaint callbacks; there is no blanket "discard unaccessed old states on abandon" rule beyond the access-move finish semantics. Native resources retire on backend completion fences, never a guessed frame counter.

## 6. Authoring-doc adjustments and honest gaps

Feedback into the authoring docs (limited): `Entity` borrowed-vs-owned semantics with `RetainInto`/`UpgradeInto`/`Transfer` and borrowed-`Release` misuse; subscription owner kinds (window-scope vs entity-scope) with `Cancel`/`Detach`/`Transfer`; task weak-capture spawn, cooperative cancel, detached-task registry; the payload freeze-until-retirement convention plus `EmitOwned`; strong-capture registration owners for `OnNextFrame`/processor equivalents. Honest gaps: all signatures uncompiled (ticket 10 tracks compiler proof); insertion-order delivery and generation ids are commitments to validate; payload retirement liveness is a labeled one-cycle-later adaptation; test determinism depends on seeded scheduling and recorded inputs, not the foreground loop alone; native retirement awaits backend tickets; leak detection is debug-only; no absence claims beyond the selected snapshots. The lease/scope selections above are delegated engineering decisions already made; review items are the validation facts and the backend-dependent retirement mechanism, not a reopened preference.
